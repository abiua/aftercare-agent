# 阶段4进度：审查链路与E1候选

2026-11-13。尚未完成阶段4验收；没有调用付费模型，没有E1效果数字。

## 已实现

`agent_kernel/review.py` 使用相同指令、证据与输出契约实现独立审查和同上下文自检。独立审查仅收到白名单公开消息、政策、提议与护栏确认事实；不传raw_data、执行者私有上下文、旧审查结果。自检额外收到执行者实际输入和确实存在的私有上下文，不补造模型思考。

仅写操作、转人工和保守关键词命中的拒绝候选触发。读操作和普通回复不触发。结构无效、引用不存在或不是原文、超时或模型预算错误时默认allow，并保存原因。未知程序异常仍抛出，不掩盖为正常放行。

修改意见只影响下一次重新生成；不递归审查。修改后仍检查硬护栏，失败抛出GuardRejected，不让被拒绝的写操作返回执行。官方适配器保留最后一次执行者响应的用量和原始元数据，不能把审查JSON当作客户回复。

## E1候选数据

构造脚本 `scripts/build_review_benchmark.py`。当前v2草案169个候选（开发79、保留90）：正确写入45、不当放弃28、错误写入82、正确放弃14。按题号排序位置交替划分，按题与参数合并重复。原对话及候选保存在本地 `.runtime/e1-review/e1-candidates-v2.json`，不公布客户模拟私有元数据。

五种固定改错类型均有实现。只有公开证据支持唯一错误判断时才生成：例如改款式时要求客户明确提到所选编号；取消原因要求最新客户文本明确说出原因；没有其他商品或支付资料则排除。记录90条排除原因。foreign_payment使用官方原始数据库中另一用户真实支付方式，但其所属人不进入模型输入。v1的纯虚构支付编号草案保留本地，未用于实验。

真实失败中的转人工另列挑战集，expected为空；不能仅凭官方0分标成不当放弃。官方成功只是正确写入的候选来源，仍需审核中间操作与当时对话，尚不能直接批量调用模型。
