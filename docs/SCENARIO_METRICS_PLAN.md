# 场景指标与贡献案例下钻

## 需求与现状

Notion 要求从能力指标按场景下钻，每项显示分母、样本量、定义版本和评分来源。专项验收要求从指标定位失败案例，能继续核对复核历史与冻结配置，并区分模型错误、程序拦截和最终违规。 [评测需求](notion_snapshot/evaluation.md#页面与主要操作) · [专项验收](notion_snapshot/stages.md#测试中台的专项验收)

| 已实现 | 待补 |
| --- | --- |
| 用例库按意图、异常类型、难度、划分筛选。用例接口把参考的 `family` 作为场景返回。 | 实验能力指标固定读取整组 `value.metrics`。实验下方状态和意图筛选只影响案例表，未改变指标样本。 |
| 实验服务对全部结果和复核记录计算指标。部分指标携带 `unknown`、`metric_version` 和详情。前端显示数值、计数／样本量及评分来源。 | 缺少后端场景聚合与指标贡献记录，页面还缺逐指标的未知数、计量单位和定义版本。现有“计数／样本量”通用列也不能解释全部分母，例如负载速率的分母是时间。 |
| 案例运行可按案例号及重复编号打开详情，查看执行证据、人工复核历史和冻结配置。成对比较可以打开任意一侧案例。 | 指标本身没有入口，也没有说明哪些案例增加了分子、只计入分母、缺证据或不适用。成对状态变化未按指标解释贡献。 |

## 分组和口径

- “全部场景”使用该实验全部计划结果。第一版支持按异常场景与售后类型分别筛选，可组合使用。场景键读每条结果已保存的 `expected.family`，售后类型读结果的 `intent`。新实验创建时已经保存参考，补跑直接继承原结果的参考。历史结果缺 `family` 时单列“历史报告未登记场景”，不得用现行用例库或文本猜测归类。内部场景键用于匹配，界面用项目维护的中文别名，无别名时给保守的中文名称并允许查看原始键。 [创建与补跑](../backend/src/aftercare/evaluation/service.py#L740) · [参考快照字段](../backend/src/aftercare/evaluation/dataset.py#L693)
- 在后端先按冻结字段选出计划结果，再用同一聚合入口对这组结果与对应复核记录计算。覆盖率使用“已结束且启动过／场景计划运行”，任务成功率使用“成功／场景已启动”，超时、执行错误和待复核按当前口径留在适用分母。另列计划、已启动、已结束、未运行、独立案例数和重复运行数。一次案例重复三次可以提供三次运行观察，独立案例仍为一个。不同场景的比率和分位数不能通过平均组值还原整体。
- 各指标保存实际计量单位和独立案例数。样本可以是运行、检查项、工具决策、引文、故障触发或模型调用。当前评分语义保持，包括最新复核版本的标签、总评无法判断时的处理、工具参数的确定性回退、费用账本不全时费用为空。按指标分别定义未知与排除；无可用样本显示“暂无可计算证据”，已观察的零显示零。补充用量审计、导入报告、发布门槛和原导出各保留当前边界。发布门槛仍基于原实验整体。
- `config.metrics_version` 是实验冻结的定义标记。当前服务读取时用部署中的指标函数计算，部分扩展行带实现的 `metric_version`，基础行没有。新接口应分别给出冻结定义与实际计算定义，所有指标行统一带计算版本。首轮复用现有公式，不因增加分组改变定义。遇到冻结定义和当前可用实现不一致，返回明确“此历史定义暂无法下钻”，保留原报告；不能把当前实现给出的数值标成历史定义复现。对旧实验缺少定义标记的情况，也使用显式历史不可用状态。

## 建议接口

沿用评测的 tester 鉴权，新增可选能力 `eval_scenario_metrics`。详情和导出现有格式保留；新增独立只读接口避免实验列表和轮询携带所有贡献明细。不触发运行、不调模型、不写评分。

| 请求 | 返回 |
| --- | --- |
| `GET /api/evaluation/experiments/{id}/scenario-metrics?scenario=…&intent=…` | `schema_version`、实验 ID、冻结数据集／配置标识、冻结与计算指标版本、状态、筛选项、选中范围、`scope_counts`、`basis_revision`、指标行。默认全实验，未登记场景采用独立约定值；空子集显示零计划与空值，非法筛选参数拒绝。每行包含现有 Metric 字段，加样本单位、已计量样本、独立案例数、未知数及其单位、下钻是否支持。 |
| `GET /api/evaluation/experiments/{id}/scenario-metrics/{metric_key}/contributors?scenario=…&intent=…&basis_revision=…&bucket=…&limit=…&offset=…` | 同一口径标识、该指标行、各类案例数和分页结果。每条含 `result_id`、`case_id`、`repetition`、机器与有效结果状态、最新复核版本、对该指标的贡献、中文解释对应的结构化原因和可核对证据定位。按 `case_id,repetition,result_id` 稳定排序，可筛“计入／需关注／缺证据／不计入”。 |

`basis_revision` 是服务器对选中范围、公式版本、结果版本及已采用复核版本的稳定摘要，并包含会影响计算的实验状态或冻结配置标识。每次响应在一致的结果和复核视图内构建。若后台运行或人工复核推进后摘要变化，下钻返回 `409 METRIC_BASIS_CHANGED`，前端提示更新并刷新指标，避免把新版本的案例与旧分母放在一起。只读接口可对当前版本重新计算，无需另建持久化数据表。长期可按实验 ID、范围和摘要缓存。

### 贡献记录

指标聚合与贡献应共用一个样本提取过程。样本由计算端给出所属案例、观察值或未知理由、证据位置。前端用它做展示与跳转，不重新评分。保留一条案例重复运行一行，可展开其中多项检查、引文或调用。一个案例可能同时有通过和失败的子项，筛选分类按子项是否存在匹配，分类案例数因此可以重叠。除比率外，结构可表达样本值、分位位置、审核资格等信息，避免强制所有指标都拆成分子分母。

| 指标类型 | 贡献解释 |
| --- | --- |
| 任务成功率、覆盖率 | 指出每次运行是否进入分母及分子，例如“已启动，超时，计入分母”“未启动，不计入成功率，仍计入覆盖计划”。 |
| 查询参数、引文支持、关键事实 | 按每个适用判断的计分口径显示通过／不通过／未知、人工标签版本或程序回退来源。保留工具索引、引用键、事实键等准确证据定位，技术键放在折叠区。 |
| 模型违规、程序拦截、最终违规 | 三项分别列记录及对应轨迹／结果。“草稿被拦截”不填入最终违规，也不能据此说任务成功。业务结果缺审计时明确显示缺证据。 |
| 费用、耗时 | 展示被计入的冻结费用记录、未审计／未定价原因和观测耗时。分位数下钻能看到纳入排序的样本及命中位置；每成功案费用分别解释总费用样本与成功案分母。零次实际调用且证据完整的记录与缺账本区分。 |
| 检索、意图混淆与宏 F1、独立案例一致性、负载窗口 | 按原始观测展示贡献，例如检索命中／参考数、预期与实际类别、同案多次运行组、负载时间区间。宏 F1 和负载峰值由全组计算，不伪造可相加的逐案得分。 |

首个可验收切片贯通任务成功率、覆盖率、草稿拦截／最终违规、工具参数正确率、引用支持率、费用和主动耗时。其他指标先由服务计算场景值，逐项核对贡献提取后再开启入口。页面应清楚显示哪些指标还缺逐案定位，全部要求的指标均可核对后再判定完整交付。

## 页面路径

1. 评测员打开一个实验，在“能力指标”上方选“全部场景”或“场景”，可再选售后类型。指标区随服务器返回切换，显示当前范围、独立案例数、运行数与进度。下方原有案例列表筛选保留为浏览工具，标签说明它只筛列表。
2. 每行显示值、样本及其单位、缺证据数和评分来源。定义版本和适用规则可展开。以“2 / 3 次已启动运行”为例，点“查看计入案例”看到两次成功和一次超时；点超时案例打开已有案例详情，可核对失败原因、原始证据及复核历史。实验上方的冻结配置一直可查看。
3. 沿用现有 URL 和案例详情路由。加可选 `eval_scenario`、`eval_intent`、`eval_metric` 参数，切换实验时清除旧范围与指标。从下钻打开案例时保留指标范围，关闭回到同一贡献列表。深链接打开的是当前数据，需留存同版证据时保存接口响应中的口径标识和实验报告。
4. 老后端没有能力字段时显示“整体指标”，不提供场景切换入口。首次交付只在单实验详情加入场景能力。后续若扩展到成对比较，须先满足现行冻结配置与案例重复配对规则，再取两侧同一冻结分组计算。缺配对时维持现有完整性提示，不能拿两个各自筛选后的独立比率当成成对结论。

## 验收

- 纯测试用两个场景和一条未登记记录，混入重复案例、超时、未运行、审计缺失及已复核修订。验证全场景复现现行指标，场景子集按正确单位重算且贡献可核对。验证比率、分位数、零值／空值、未计入与未知、适用子项和最新复核版本的统计边界。
- 受控 API 和浏览器覆盖切换场景时改变实际返回分母、从失败项打开精确重复编号、返回指标页、刷新深链接、旧后端和冲突重载。以同一行含通过和未知子项覆盖分类重叠，检查分页不漏不重。
- 独立测试环境只读验收一份已存在、跨场景且带重复编号的实验，手算一项分母并和贡献列表核对。可选另一份历史无场景记录检查降级。真实浏览器证据需单独记录。无需启动新实验或填人工评分。
