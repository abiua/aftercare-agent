# P4 程序优先路由与协作实施计划

本计划供 P3 接线完成后实施。当前 P3 把会话资料归档到决策快照，旧图实际读取最后一条相关客户消息及业务快照。以下新输入、并行角色和局部补查均尚未验收。

## 1. 从现有系统增量接入

| 当前入口 | 复用与新增 |
|---|---|
| `intelligence.graph._gate/build_graph` | 保留定向退款查询、明确缺证、政策阻断和等待中断。旧 `single/multi` 及检查点照常解释。新聊天运行持久化 `graph_profile=CHAT_V1` 与已选实验架构，工作进程按版本取图。禁止用新图解释旧检查点。 |
| `intelligence.graph._run_role/TOOLS/_verify` | 当前所有角色使用相同工具，取证、政策、核验串行，冲突整段重跑。新图重用 ModelRunner、结构化校验、引用条件和业务 `validate_draft`，按角色拆工具和输入视图。 |
| `intelligence.service.AgentService/RunAudit` | 继续使用已提交的 AgentRun、Celery 派发、检查点、周期/租约栅栏和费用账本。在新版本图执行前绑定实际调查输入与路由规则摘要，发布前重比有效版本。 |
| `conversations.decisions.freeze` 与 P3 projector | 当前存有原消息、附件、观察、业务状态和政策。新输入构造从这份授权快照派生，独立记录实际进入模型与工具的引用。最终投影到 P3 Candidate，沿用人工决定、客户确认、财务审批和执行账本。 |

P4 不重启或重新编排 P1/P2 公开消息。聊天 API 继续由服务端决定路径。普通客户无模型、架构、工具或预算选择权。内部评测才接受固定实验臂。P4 准入不得悄悄启用客户视觉登记。需要新图像观察时复用 P2 已授权且受限的视觉阶段，并保留真实能力与数据范围守卫。

## 2. 实际输入与复杂度

由已授权会话、活动事项、订单行和工单创建 `InvestigationInput`，内容从已提交且同事项的 P3 冻结输入派生：

- `conversation_id, issue_id, case_id, input_through_seq, source_snapshot_sha256, relevant_input_sha256`，选入的客户消息序列、去除身份冗余的文本及原始消息引用。生成预先定义的有界消息投影，遇超限输出明确澄清或转人工，避免静默截掉具有冲突的信息。
- 附件只提供同事项标识、原始摘要和关联消息。已发布的 P2 观察用原图和发送图摘要、观察类型、版本和不确定性引用。原图仅允许经受控视觉通道。客户陈述和观察进入单独的数据块，不作为系统指令或已核实事实。
- 按工具所需提供授权事实及政策。每次调用审计记录实际文本投影摘要、读取证据 ID、角色可见工具和模型请求的输入承诺。评测可区分归档资料、选入资料、实际模型可见资料。
- 启动、恢复、合并、发布复核事项、授权和相关依赖。无关回执或致谢可增加消息序列，保持相关输入摘要。新订单、争议范围、补图、已核实事实或政策变化使对应节点失效。过时结果只记已发请求、用量及不确定状态。

`RouteDecision` 持久记录版本、路径、触发原因和支撑证据，分别保存 `complexity_features` 与 `financial_risk`。路由判定顺序如下。

1. 程序先处理已授权定向退款、对象不明澄清、确定缺证、明显不适用及硬阻断。给出确定事实、明确需要的材料或转人工。记录零模型调用。
2. 范围明确且无已知复杂因素，进入强单 Agent。金额高本身仍可走单 Agent，审批/复核按既有风险规则收紧。
3. 订单行或包裹的归属相互影响、客户陈述与可信数据冲突、条款范围或优先级冲突、或关键事实可通过独立取证进一步核对，进入多 Agent。无法在授权工具内核实的硬阻断仍由程序转人工。
4. 强单发现真实复杂因素时，只允许一次有记录的升级。已有可核验证据可复用，保留剩余预算和截止时间；多 Agent 的首轮仍不给某角色看另一角色的未核实意见。

## 3. 工具及执行图

工具读取同一冻结事实快照。参数用严格 schema，业务对象由绑定范围给定，角色只能从服务器生成的可见 ID 中选择。工具返回有来源的事实或候选条款；缺失、冲突和拒绝各自记录。工具无审批、写工单、支付、网络搜索或跨客户查询权限。

| 工具 | 输入与返回 | 路由角色 |
|---|---|---|
| `read_order_lines` | 已绑定订单内行 ID。返回实付、配送、产品、剩余额度或可用数量，带业务记录版本 | 事实、强单；核验仅经明确补查任务 |
| `read_material_evidence` | 同事项附件或材料 ID。分别返回原图引用、未核实视觉观察、可信材料审核状态和版本 | 事实、强单；核验仅经明确补查任务 |
| `read_refund_execution` | 已绑定订单内明确执行 ID。复用退款定位，区分无记录、提交中、未知和模拟回执 | 事实、强单 |
| `search_applicable_policy` | 固定范围内主题和事实条件键。复用适用版本选择、BM25/实际已配置混合检索及检索审计 | 政策、强单 |
| `read_policy_clause` | 已可见条款编号、版本和对象范围。返回原文、条件和适用快照引用 | 政策、强单 |
| `request_targeted_check` | 核验主张 ID、冲突引用、允许的目标工具及理由。只产生受限补查任务，不直接扩权 | 多 Agent 核验 |

强单从同一输入自主决定取证顺序，最多若干模型轮与总工具调用，限额在实验计划中显式冻结。每轮先验证整个工具批次，无依赖的只读调用可并行，从同一冻结输入读；依赖结果的查询进下一轮。按工具调用 ID 稳定归并，重复同参数读取复用同版本证据并保留调用审计。单 Agent 三阶段评测臂顺序为调查、政策、核验，仍由同一个逻辑 Agent 完成，复用相同工具总集和结算规则。

多 Agent 从程序路由显式分叉为 `fact_investigation` 与 `policy_investigation`。两者从同一冻结输入并行，不读取彼此的输出；政策侧可以读取程序允许的原始条件事实键。LangGraph 状态用按角色/任务 ID 分区的 reducer，避免并行覆写。合并节点只接收两侧完成、缺失或失败的独立结果。随后反例核验检查能否用来源证明候选动作、对象、金额/数量和政策适用，生成结构化反例。最终程序仍重跑引用条件和业务草案校验，阻断项交 P3 非执行候选。

## 4. 证据关系、补查和预算

每个 `EvidenceRef` 包含 `source_kind, source_id, scope, version_or_sha256, observed_at`。每个 `Claim` 含 `claim_id, subject, predicate, value, supporting_refs, conflicting_refs, dependencies, role_task_id, state`。状态至少支持 `SUPPORTED / CONTRADICTED / UNRESOLVED / STALE`。角色提出主张后，由程序根据来源及工具可见范围检查标识和对象。未核实观察不能支持身份、因果、责任或已批准的主张。

反例结果使用 `claim_id, contradicted_field, supporting_refs, contradicting_refs, verdict, requested_check`。没有可信数据时保留未决，不由票数或模型自报置信度选择。局部补查用结构化 `target_role, claim_ids, allowed_tool_ids, input_digest, dependency_versions, deadline`。新结果替换相关节点的当前指针，旧证据和旧主张保留。沿显式依赖重算受影响的主张及决策。一次补查只触发相关角色，超过冻结轮次或复核仍未定则明确交人工。

继续使用 `RunAudit.begin_attempt` 的事务预算、`ProviderLimiter` 和队列租约。首轮分叉前预留核验所需额度，运行时在同一运行和周期锁下原子检查尝试数、费用和截止时间；并行角色各有稳定逻辑 ID。未知尝试保留费用预留，接管者不重发同一逻辑调用。队列失租或相关输入变化后停止新调用；晚到响应可补记审计。强单升级、重试、补查和视觉阶段使用同一案件上限，未使用额度的处理写入预登记方案。工具调用也有总量和耗时界限。

## 5. 实施与验收顺序

1. 实现独立输入构造、路由、工具注册及版本调度。验证旧运行兼容、输入/引用实际进入请求、无关消息不失效、确定性路径 0 调用，以及普通高金额案例仍需严格审批。
2. 接强单循环和同批无依赖工具并发。验证有依赖调用不能并行、边界参数与权限、重放/预算耗尽、有效草案和明确非执行草案。
3. 加并行独立事实与政策、反例核验及一次局部补查。用同步点证明真实重叠而非时间推断，记录角色看不到对方初稿。复杂案例须观察到证据冲突定位、仅相关角色重查、未变证据复用及最终规则核验。测试迟到、失租、无独立证据及超预算。
4. P5 固定三臂与消融。强单、单 Agent 三阶段和新多 Agent 逐案配对。使用同一模型别名/版本、原始输入与视觉设置、工具总集、上下文和费用/时间上限。阶段间有权限区别但全臂信息可获得性应一致，报告实际读取、调用和支出。分别去除独立取证、反例核验、局部补查，保留相同程序安全门，明确替代流程。程序路径零调用作参照，分常规和复杂报告，保留未知、失败、未执行和人工盲审分母。历史单/多报告不能证明新架构性能。

合成测试可证明结构与栅栏。生产级对照还需受控真实调用、浏览器及独立复核。视觉实证仍按图像来源、模型兼容和观察用途报告。
