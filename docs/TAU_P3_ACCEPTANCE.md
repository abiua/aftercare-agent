# P3 RAG 阶段验收（2026-11-12）

状态：P3 隔离 RAG 能力与真实服务阶段验收通过，仍有检索质量坏例。已停止在 P3，P4 未开始。

## 交付范围

P2 已核验原文 → 固定长度/结构切片 → 多语 embedding 与 BM25 → Milvus/pgvector 余弦召回 → RRF → cross-encoder rerank → 同权限父级上下文 → 带引用的模型回答。

| 组件 | 本轮方案 |
| --- | --- |
| 原文与扫描 | 复用 P2 解析；[OCR倾斜校正方案](TECH_STACK_OCR.md)纳入技术栈，needs_review 扫描不得自动入可信索引 |
| 切片 | 固定450字符/70重叠，以及按条款/标题/表格保留的结构片；保留父级上下文、原始块和位置 |
| 向量模型 | 固定 revision 的 paraphrase-multilingual-MiniLM-L12-v2，384维；CPU ONNX量化，128 token 上限 |
| 词法与融合 | BM25 + dense，RRF k=60；默认召回20、返回5 |
| 重排 | 固定 revision 的 mmarco-mMiniLMv2-L12-H384-v1，真实多语cross-encoder；512 token上限 |
| 存储 | 独立 Milvus standalone 与 PostgreSQL/pgvector；相同向量、精确余弦对照，未宣称ANN或企业规模性能 |
| 访问与适用 | 政策范围、角色、版本、生效区间分开校验；无日期来源只允许显式版本固定并标unknown |
| 生成 | 复用项目配置模型，一次有界调用；父级证据作为数据，引用ID与原文片段核验，保存原始输出 |

CLI由本机操作者指定角色/政策范围；这是隔离检索工具，不是新上线的客户鉴权接口。现有客户聊天及旧业务默认路径未替换，正式售后流程接线属于后续阶段。引用存在和字面定位正确不等于回答所有主张已自动通过语义核验。

## 评测边界

18条代理编写的冻结开发查询，包含英文和中文，基于同一固定τ²-bench零售政策。标签在检索前冻结，未把隐藏客户设定或标准答案放入索引。既不是官方τ成绩，也不是独立真人金标。

旧800/120固定切片全部10片超过128 token，已将静默截断记录为坏例并保留报告。现模型遇超长输入直接拒绝，新450/70固定切片18片最长118 token，结构77片最长83 token；这些上界只针对本次语料。不能宣称450字符对任意语言都不会超限。

检索指标按每条查询对原文证据的覆盖、排序计算。主切片Recall与父级扩展覆盖分别保留，不能靠父级带整篇政策虚增主召回。实际坏例见 [分析](TAU_P3_BAD_CASES.md)。下表为恢复后真实数据库实测，不以测试数量代替检索效果。

## 实测结果与主代理结论

同一批18条冻结开发查询、相同查询/文档向量，两库结果一致：

| 路径 | 固定切片 Recall@5 | 结构切片 Recall@5 |
| --- | ---: | ---: |
| BM25 | 50.00% | 50.00% |
| 向量召回 | 63.89% | 50.00% |
| 混合召回 RRF | 63.89% | 69.44% |
| 混合召回＋语义重排 | 72.22% | **80.56%** |

结构＋重排的 MRR@5 为0.8102、nDCG@5 为0.6766。相比结构BM25主证据Recall@5提高30.56个百分点；相比同预算固定切片重排提高8.33个百分点。两个重排方案各仍有6条查询未找齐全部参考证据，不能宣称业务回答正确率80.56%或问题已全部解决。

两个策略×两库×三种稠密相关模式×18查询，共108次对应Top5排名全部一致；14组配置共252条查询执行，含重复运行同一18查询，不是252个独立样本。84个访问/版本/日期探针均通过，也不是84种独立业务场景。最终引用的原文定位检查通过，不能解释为每条政策适用已获人工确认。

Milvus 2.6.9、PostgreSQL 16.12/pgvector 0.8.1 在独立Colima profile实际运行。生命周期使用3条明确合成记录：写入、限定候选、更新内容与向量、删除、容器stop/up、恢复读取、drop/create重建全部实测。报告保留容器ID和镜像ID、变化的StartedAt与健康状态，证明是服务重启而非仅重连。四阶段两库最大分数差9.05e-8。真实77块政策另建持久catalog，在新进程与服务重启后复用，同库前后完整结果一致；实际政策catalog采用不可变快照，新版本需新建catalog，不称在线热更新。

结构重排本机P95（含共享查询编码计时）pgvector约139.6ms、Milvus约142.5ms；单轮、小样本、串行且有预热，不是并发性能、服务SLA或数据库优劣结论。采用精确检索用于公平对照，ANN与容量压测未在P3验收。

完整生成路径使用重启后的Milvus持久索引结果，再调用一次项目配置的真实模型。主代理和审查代理逐句核对：送达前提、订单及商品确认、退款方式、状态和邮件均有原文；退货政策未规定退款时限，回答没有挪用取消/修改订单的5–7工作日。生成耗时约8.62秒，按本地配置价估算$0.00517925，非账单。此为一条生成示例，语义审核并非自动评分器普遍保证。暂停前那条内存检索生成也已完整保留。

主代理最终相关回归32项通过，Ruff与diff检查通过。原有620份数据/报告及旧脚本哈希不变，固定评测查询/标签摘要与前轮一致。Sol6.1子代理分工实现及独立复核，主代理集成、检查实际原始报告和模型答复。

## 实际问题与修复边界

1. 固定800字符片段被模型静默截断：保留旧报告，改450/70并显式拒绝超token输入；未宣称任意新文档都可直接编码。
2. Milvus健康接口恢复早于集合查询可用：保留首轮503日志，读操作对503有限重试。成功生命周期记录一次暂态；报告的7.49秒是compose恢复健康的时间，不包括全部首次查询RPC耗时。
3. 两个Milvus适配器共享SDK连接，关闭其中一个影响另一个清理：采用每适配器独立alias。原报告的两处清理失败保留，新报告无清理失败，临时孤留集合已按本轮集合名清理；持久catalog保留。
4. 召回遗漏与重排替换必要证据仍存在，见坏例。没有为提高分数改标签或把答案送入模型。
