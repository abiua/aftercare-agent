## 目标与边界

保留现有客户聊天、图片、工单、权限、客服审核、独立审批、幂等模拟执行、检查点、队列与历史评测。以固定版本 τ-bench retail 作为主要政策、业务任务与模拟客户来源。数据属于合成基准，不称真实企业数据。原基准模式与增加 HITL、图片证据的项目扩展模式分别报告，修改后的任务不冒充官方成绩。

模拟客户读取隐藏用户设定；售后 Agent 只能看到公开政策、客户实际发送的信息及授权工具返回的业务数据。评分参考、预期动作、隐藏用户条件不进入 Agent 输入。原始任务中允许客户提出多个诉求，不能提前把整段任务当作客户第一句话。

## 评测规则

先比较切片与检索，再固定模型比较协作，最后固定架构比较模型路由。开发与最终评测任务分开；用户模拟器配置固定并重复试验。优先依据数据库最终状态和业务规则，人工/模型评分明确身份及局限。保留 Agent 人工介入前的原始决策，不以客服修改覆盖。标准基准最终状态不强制唯一工具序列；项目扩展审批规则另行验收。

τ-bench 政策规模不代表企业文档规模。原始基准、文档/多店铺/图片扩展、容量测试语料分别登记；复制语料仅用于压力测试，不能证明检索效果。当前 P1 仅交付可复现的数据层和可见性边界，不等于已有真实模拟用户多轮对话、官方评分通过或生产接线。

## P2.1 OCR 质量优化与对比（2026-11-12）

用户授权对比 PaddleOCR 与现有方案，补中文、复杂表格和低质量扫描测试。保留原 P2 Tesseract 英文结果，新建隔离样本/运行环境，比较旧英文配置、中文 chi_sim+eng 基线与 Paddle 实际输出；不把语言配置不匹配的优势当模型收益。测试内容与退化参数在识别前冻结，模型不可读取预期答案或评分字段。普通文本与复杂表格、清晰与低质分别报告，失败页保留在分母。样本为代理编写、主代理视觉复核，非独立真人金标或企业总体准确率。

指标：明确归一化的字符错误率、金额/否定/日期/例外等字段精确匹配、结构化表格 cell 位置/rowspan/colspan 及内容、耗时与初始化开销、工具/模型版本与哈希。无表格结构输出记为不支持，不能用全文出现某金额冒充行列匹配。保留原文/识别观察/修订版本和 bad case，不硬编码 OCR 错字纠正。

验收：公开模型实际运行；同页输入对照；评分器有坏例测试；中文和低质页面视觉确认；旧572文件哈希保护；新依赖隔离且说明复现；只提交可验证结论，不预设 Paddle 必然优于基线。P3 不自动启动。

## P4 当前实施与验收范围（2026-11-12）

现状与差异：P3为独立检索CLI，聊天尚未调用；现有聊天与退款闭环可复用，但更正后缺少明确的同事项恢复与可追溯当前记忆。本轮复用原工单、分析代次、排队任务、客服/客户/审批/幂等账本，不重写业务系统。

1. 授权规则RAG：正常店铺订单查询原授权政策目录，经真实Milvus、BM25、RRF与cross-encoder检索，保留精确政策版本和原工具引用。τ上游规则保留独立参考，不能混作旧店铺订单授权。政策咨询走异步队列及新消息代次校验，避免长时间持有业务行锁。
2. 当前会话记忆：由原始已发布消息、明确对象和证据来源派生，可刷新/重启重建；主诉与普通补充分开，客户说法不升格为核实事实。更正使旧候选失效；客服可沿同工单确认更正并明确选择仍适用旧图，旧模型观察不自动复用。订单/商品变更继续明确确认。
3. 界面：客户可展开政策依据；客服看到更正及照片选择/理由，确认更正不等于审批退款。客户不选择模型或Agent模式。
4. 隔离验收：新业务PG/Redis/S3、API/worker/前端，复用独立tau-rag虚拟机和Milvus，原default环境及旧数据保持不动。保护631份旧data/reports。分别做策略来源/记忆纠正/越权/旧结果隔离测试、正常HTTP闭环与浏览器验收，真实模型调用和离线回归分别记录。
