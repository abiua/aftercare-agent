# 评测逐项人工标注前端契约

本次只读核对现有评测后端与已保存报告。表单收集人工判断并展示证据。程序检查、引用前提状态、候选条款和旧复核记录可供阅读。

## 提交与键来源

`POST /api/evaluation/results/{result_id}/reviews` 由测试员提交。请求包含当前案例运行的整数 `expected_version`、人工选择的总体 `decision`、去掉首尾空白后 1–1500 字的 `notes`，以及可选的 `annotations`。总体和逐项选择均为 `PASS`、`FAIL` 或 `UNKNOWN`。三个类别各最多提交 100 项。接口限制枚举、类别和数量，未逐个检查键是否存在于本结果。因此页面从以下数据构造键，禁止任意录入、自动补齐或由候选数据生成键。 [接口模型](../backend/src/aftercare/evaluation/api.py#L62) · [写入服务](../backend/src/aftercare/evaluation/service.py#L997)

| 分组 | 可提交键 | 可展示证据与计分边界 |
| --- | --- | --- |
| `tools` | 在完整的 `result.trace` 中筛出 `kind === "tool"`，保持原顺序后取从零开始的字符串索引，如 `"0"`。跨角色和周期连续计数，筛选或折叠后保留原索引。 | 显示角色、工具名、参数、事件编号和结构检查结果。`call_id`、`seq`、业务脚本步骤、`tool_validation` 和 `model_validation` 都不作为键。空参数对象表示记录到空参数，字段缺失表示没有参数证据。逐项标签供参数业务正确率使用，工具选择率和 schema 有效率有各自的计算来源。 |
| `citations` | 直接使用 `result.actual.citation_audit[].key`，例如 `POL12@1.0`。 | 按精确 ID 和版本在 `actual.events` 各步骤的 `output.citations` 查原文。多个周期和引文片段可以同屏展示，同一键只标一次。候选 ID、已读政策、角色提到的 ID 或单有引用展示的旧报告都不能替代审计键。原文匹配、版本适用和业务前提状态可作上下文。 |
| `facts` | 使用 `result.expected.required_facts` 中的原始字符串，例如 `selected_line`。界面可加中文别名，提交仍用原键。 | 显示事实要求及实际案例快照、脚本结果或工具证据。没有对应可核对事实时可留空或选择 `UNKNOWN`。 |

引用审计由评测运行器从各脚本步骤实际发布的 `output.citations` 聚合。对同一个 ID／版本，任一已知不适用记为 false；全部已知适用才记 true；其余为 null。它衡量冻结快照里的版本适用性，引用支持率仍读取人工标签。若旧报告缺少该审计数组，页面提示历史报告缺少可标注的引用审计；若数组为空，提示没有可标注的已发布引文。缺组仍允许只提交总体和备注。 [引用审计生成](../backend/src/aftercare/evaluation/observations.py#L82) · [工具口径](../backend/src/aftercare/evaluation/metrics.py#L126) · [引用与事实口径](../backend/src/aftercare/evaluation/metrics.py#L238)

## 未知与历史版本

- 新表单所有项目保持未选择。人工明确选择 `UNKNOWN` 时可保存该值，未选项从本次映射省略。对引文和事实，两者都进入未知；没有有效人工样本时分母为零、比率为空。工具的人工 `PASS` 或 `FAIL` 优先。如果工具标签为 `UNKNOWN` 或省略，但恰好同时有冻结参数参考和实际参数对象，指标会回退到确定性匹配，否则进入未知。因此不应承诺选 `UNKNOWN` 一定覆盖已有程序判断。 [比率分母](../backend/src/aftercare/evaluation/metrics.py#L64) · [参数回退](../backend/src/aftercare/evaluation/metrics.py#L149)
- 每次写入新增一条带复核人、时间、版本及完整映射的历史。统计只取最近一次复核的映射，三个类别均无合并。最新总体为 `UNKNOWN` 时，统计忽略该次逐项映射，也不会回退到前一条。新记录省略旧键或提交空映射后，旧标签仍在历史中可见，但退出当前统计。对已有逐项标签的结果，保存前提示本次提交会替代当前统计用的标签；无逐项选择时仍支持明确确认后只写总体和备注。历史空映射显示「未提交逐项标注」。 [最新标签选择](../backend/src/aftercare/evaluation/metrics.py#L20) · [历史序列化](../backend/src/aftercare/evaluation/service.py#L202)
- 总体结论影响有效结果的独立规则仍保留。`machine_status=NEEDS_REVIEW` 时，人工总评 FAIL 可令有效结果为 FAILED；总评 PASS 还要求有确定性检查且全部通过、存在合格观测来源，才能令有效结果为 PASSED。页面始终由人选择总评，逐项选择、空映射或全部程序检查通过都不能自动生成总评。结果复核与数据集独立金标分别存档。 [有效结果](../backend/src/aftercare/evaluation/service.py#L214) · [独立金标契约](../backend/src/aftercare/evaluation/gates.py#L83)
- 表单打开时保存案例运行版本，提交带 `Idempotency-Key`。同键同内容重放返回原历史记录，同键改内容报冲突。版本不一致返回 `VERSION_CONFLICT`，刷新并请复核者确认最新历史后再打开表单。网络中断时只在内容与版本完全相同的情况下沿用键；不可静默换版本重发。只给机器状态已结束的结果开放保存。 [版本与幂等](../backend/src/aftercare/evaluation/service.py#L175) · [已有前端重试机制](../frontend/src/hooks.ts#L31)

## 中文判题与证据对照

把问题写成可直接根据案例回答的中文，内部键只放在可展开的技术明细里。

| 分组 | 复核者看到的提问与对照 |
| --- | --- |
| 工具参数 | 「这次查询用的是正确的订单或条款吗？」并排显示工具查了什么、填写的参数和应核对的业务范围。空参数说明「这次查询没有输入参数」，缺日志则说明「这份报告没有记录查询参数」。 |
| 条款依据 | 「这条原文能支持这次答复吗？」并排显示应用实际发布的结论、相关事实和引文。用中文区分「已匹配条款原文」「当前未找到满足条件的记录」，让复核者核对条款所说的事与本案是否一致。 |
| 关键事实 | 「答复有没有准确交代这项事实？」用「申请的是哪件商品」「系统有无退款执行记录」等业务问题显示待核对事实，再展示有记录的订单行、支付或材料审核情况。 |

逐项选项按分组显示「正确／有依据」「错误／依据不足」「无法判断」，另保留未选。工具组遇到已有程序参数比对时，在选项附近说明「无法判断表示你没有给出人工结论，指标仍可能使用已有的程序比对」。总体结论与每项选择分开；汇总数字不能替代证据阅读。

## 表单验收

1. 以三角色样本检查分组、条目顺序、证据与保存请求。初始全未选，只提交明确选择的原始键。总体与备注必须独立填写。三组分别限制 100 个已选项，超过时阻止提交并说明，不能截断或重新编号。
2. 用浏览器 fixture 和旧报告覆盖无工具、无引用审计、缺历史参数。验证空分组提示、旧空映射和程序检查均不生成任何标签。再用受控样本覆盖工具显式 `UNKNOWN` 的确定性回退与引文／事实的未知分母。
3. 模拟已有标注的结果，验证再次保存时提示替代范围、前版历史仍可见、结果版本正确递增。模拟冲突及同键重放，确认未自动换版本或生成重复记录。真实浏览器先只读核对；未经人工判断的 POST 只使用专用受控样本。

本次未修改后端或历史报告，未调用服务，也未提交任何人工评分。
