# P4 第二轮提示超过本地上限

在冻结版本 d8cb2e4 的合成事项上，真实 Terra 首次请求成功。模型返回了订单行、材料和政策搜索三次工具调用，工具均在本地完成。第二次请求组装时触发 INVESTIGATION_PROMPT_LIMIT，最终留下待客服处理的候选。真实 HTTP 只有一次，响应状态 200，提供方报告输入 6,132、输出 246 tokens，按现有登记价格估算 0.00889425 美元。此结果验证了文字及工具调用的兼容性，决策质量仍待验证。证据见 [chat-p4-text-live-20261111.json](../reports/chat-p4-text-live-20261111.json)。

## 定位

从独立 5195 栈 PostgreSQL 的只读事务取出该次运行冻结的 DecisionScope 和 ModelAttempt 中已归一化的首轮工具参数。用冻结代码和真实记录组装原请求，只输出长度。政策检索的原始诊断包在当次中止后未完整保留，复算按实际审计中的 11 个返回 ID 重建原始记录，省略检索诊断字段。因此第二轮原格式的数字是下界。

本地估算器以消息 JSON 的 UTF-8 字节长度加 256 作为保守输入量。首轮真实 wire 为 17,557 字节，提供方输入为 6,132 tokens。表中的复算值用于解释应用内拒绝。第二轮没有提供方用量。

首轮输入 JSON 本身为 9,665 字节。每条目录引用均重复相同的会话、事项、工单三元组。工具回复既在 refs 返回证据身份，又在 records 中逐条重复身份及三元组。政策搜索五条政策的完整 data 总计仅 1,975 字节。只移除工具定义仍超过上限，缩短政策正文也无法处理重复结构。多 Agent 核验阶段还会同时放入原始回复和按 ID 重建的相同原始证据，存在同类结构性问题。

## 最小修复

1. 为 P4 模型请求引入明确版本的证据投影。消息外层保留事项三元组及输入摘要。每条证据保留类型、ID、版本或内容摘要、可用的观察时间、可信来源分类和完整 data。由程序校验每条证据都与外层范围一致。采用定义清楚的定长索引结构或短字段，省略值为 null 的可选时间。任何范围不一致显式转人工。
2. 工具给模型的同一回复只编码一次完整记录。审计保留工具名称、参数摘要、原始回复摘要、按序证据引用和完整检索诊断证明。模型保留诊断所需的检索模式及结果顺序，诊断证明的哈希和向量信息由程序保管。跨回复重复记录如需引用去重，只有同类型、同 ID、同版本且内容摘要一致才可引用先前记录。同 ID 但内容冲突显式阻断。
3. 核验角色以相同证据投影读取原始字段和版本。原始记录存放一次，各工具收据引用该记录，另附工具特有结果，例如退款定位状态。不能丢掉反例或依赖项。继续维持角色权限、输入 24,576、输出 900、预算、调用和工具次数上限。
4. 每次尝试前记录程序估算、去掉工具定义后的估算、证据行数及各部分长度。超限事件记录估算及阶段，保留未发送状态。禁止静默截断正文、删除用户陈述或跳过核验。若仍超限，保留明确待客服状态。

我用真实案例的同一 17 条工具返回记录试算了一个紧凑表示。所有 17 条的 data、来源、版本与非空时间保留，范围统一在外层，工具回复不重复记录中的 refs，诊断字段独立保管。第二轮估算含原工具定义为 19,808，移除定义为 17,706。该试算没有添加正式投影版本和字段说明，也没有运行真实模型，结果是修复方案的体积依据。

## 验收

- 用此次冻结快照的等形合成夹具复现三工具同批。断言第二轮进入真实 ModelRunner 的注入传输，含工具定义估算仍低于原上限，所有 17 条记录能逐字段还原，特别是政策原文、材料审核及失败或未知状态。
- 对订单、材料、政策和退款查找覆盖空结果、重复身份、同 ID 不同版本、错误范围和仍超限，确认无未审计省略、无额外提供方调用。
- 核验角色收原始数据而不是角色转述。用同一记录同时经两种工具读出的冲突夹具，确认原始内容只编码一次、每次读审计可对照、被废弃依赖仍阻断金融候选。
- 旧运行保留其原提示或在恢复时显式转人工。新投影不得用相同逻辑 ID 复用旧提示的模型结果。真实兼容复验需另行使用有界协议，此次原报告保留。

## 修复验证

compact-v2 保持 24,576 的上限。读取同一合成事项的实际冻结范围和首次三个归一化工具调用后，以实际图和 ModelRunner 注入传输复现。政策搜索使用当时返回 ID 的原顺序，读取该范围中的完整冻结记录。未重新调用检索服务或真实模型。第二轮带工具定义估算 21,106，无工具定义估算 19,004。两轮注入传输经过三次工具收据和 17 条证据，进入受控的金融建议校验并完成。该校验使用明确的受控断言。仓库另有实际 BusinessService 规则及 P3 候选集成测试。

私有审计保存原始工具回复。客服、客户和测试员的通用事件接口均只收到该私有事件的空内容。客服和测试员可读取另行生成的工具审计摘要和预算估算。恢复旧提示绑定将明确进入待客服处理，既有已完成历史保留。真实提供方下的第二轮、最终候选和多架构质量仍需单独验收。
