[真实复验](../reports/chat-p4-compact-text-live-20261111.json)共发出 4 次 Terra Responses 请求，均为 HTTP 200。估算费用 0.01614765 美元。三轮输入预检分别为 12,446、20,524、21,833，均低于 24,576。只读工具链确实继续执行，最终是 NEEDS_REVIEW / MODEL_INCOMPLETE，未通过业务候选验收。原报告保留。

## 两次失败

| 位置 | 持久审计 | 影响 |
| --- | --- | --- |
| 第 2 轮，第 1 次尝试 | 5196 PostgreSQL 只读回查的 model_validation 指明字段 tool_calls、错误 TOOL_BATCH_LIMIT。首轮已调用 3 个工具，本轮按每批最多 4 次及全阶段剩余额度校验。 | 整批拒绝，未执行该批任何工具。失败响应及参数数量未持久化，无法确认超限批的实际大小或工具名。一次受控修复成功，仅查读一条已选政策。 |
| 第 3 轮，第 1 次尝试 | 审计为 FAILED / MODEL_INCOMPLETE，SDK 返回响应。用量为 900 输出 tokens，其中 272 为 reasoning。失败响应结果为空。 | 代码在解析前拒绝提供方不完整响应。900 与实际请求的输出上限相同，强烈指向输出额度耗尽。账本未保存提供方原始 status、finish_reason 或 incomplete_details.reason，无法独立确认精确子原因或剩余所需 tokens。 |

已登记 Terra 的 output_tokens 为 900。更直接的是 ModelRunner.TaskSpec 的默认 output_reserve 为 900，供准入、费用预留和 HTTP 请求共同使用。本次验收门也校验 max_output_tokens 为 900。这个限制同时存在于实际生产代码默认路径和验收协议。仅调高外部验收脚本无法改善已冻结 worker，且会和 wire 限制冲突。

## 建议

在内部 P4 请求中显式配置有界输出，首选 1,800。保留旧调用默认 900，允许新输出配置进入登记能力检查、上下文检查、费用预留、角色保护预留和 HTTP 参数。不要把登记上限更新描述为已验证生成质量。运行协议将实际配置值固定到模型登记、计划摘要、每笔 wire 限制和回归测试。原工作流的证据、结构化主张、审核及字段校验完整保留，输出不完整继续禁止候选发布。
