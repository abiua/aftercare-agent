# 模型工具参数修复与真实路径复验

本批使用独立合成订单、真实模型 API 和模拟财务执行。历史尝试逐轮保留；不将客服修改算作模型成功，也不将自动化材料审核算作独立人工评测。

## 修复范围

- V7 工具参数提供冻结作用域内合法值，参数拒绝返回安全的结构化诊断；业务权限仍由程序核验。
- 工具回执在同一角色、同一阶段内复用已展示记录的引用，原始回执不变。核验输入进一步对重复引用和共同字段编码，保留完整还原能力。
- 政策工具显示冻结版本键和原标题，帮助选择条款；实际读取后才获得引用资格。
- 输出结构明确退款金额、换发数量、补证缺项等条件约束。新验收显式冻结输出额度 4096；历史未设置的记录沿用 1800。
- 专用验收传输丢弃响应 Set-Cookie，避免共享 SDK 客户端在下一次请求带入 Cookie；发送端限制保持。保留发送前诊断、原生账本及未知结果阻断。

## 本轮复验准备

普通第 8/9 轮显式添加单条合成测试审核观察：商品原图、L01、可见破损、受影响总数 1。它绑定原始消息、附件摘要和材料版本，不声明真实性或运输责任。验收要求模型实际读过该记录并独立提出合格退款候选，后续客服仅采纳，不修改模型输出。

复杂第 2 轮保留双商品与包裹对应争议，要求事实与政策独立取证、核验实际执行并形成有证据支持的结果。局部补查单独报告，未发生时不得写成已验证。

本节为准备状态，真实复验结果将在执行后追加。

冻结版本根代理完整非 PostgreSQL 回归：1144 通过、2 跳过、40 项 PostgreSQL 检查未选中。专用路径验收另使用实际 PostgreSQL、对象存储和队列。启动健康检查现给 Celery 命令 20 秒、总等待 90 秒，仍要求实际成功返回，不跳过检查。
