# E1补充：真实放弃片段小测

2026-11-13。样本是首轮记录里官方判失败且发生转人工的全部20个片段（9道题，三种旧架构），即E1候选文件中原先未标注的 `real_abandon_challenges`。独立审查M1与同上下文自检S2各判一次，共40次调用，全部结算，无技术回退、无重跑，费用$0.59（上限$2）。脚本 `scripts/run_review_challenge.py`，原始结果在 `.runtime/e1-review/challenge-v1/`。

## 标签与评分

标签来自官方标准答案：转人工时仍有未完成的标准写操作或应告知的信息，即视为放弃过早。20个片段全部属于这一类，标签不进入模型输入。评分规则在运行前写入 `rubric.md`：A＝要求修改且下一步指向官方剩余操作；B＝要求修改但方向不对；C＝放行。A/B由人工对照判定，不是程序自动计分。

## 结果

| | A 命中 | B 方向不对 | C 放行 |
|---|---:|---:|---:|
| 独立审查M1 | 5 | 4 | 11 |
| 自检S2 | 4 | 5 | 11 |

两种方法的放行/修改判定20条完全一致。唯一差别在任务36：M1提到可改成更便宜的款式（接近标准答案），S2只提了整单取消。这一条属于边界判断，不足以支持“独立审查更好”。

只看强单Agent的6次转人工（最终批次真正的提升空间）：命中1次（任务27），方向不对1次（任务32），放行4次（任务18、39、77、111）。

| 片段 | 判定 | 说明 |
|---|---|---|
| 27 ×3 | A | 指出退货和换货都在范围内，要求继续并让客户在冲突时选择 |
| 42 多Agent | A | 指出不能因政策歧义转人工，应直接提交换款 |
| 36 多Agent | M1 A / S2 B | 见上 |
| 32 ×3 | B | 只要求先告知快递单号再转人工；客户尚未说出的取消和退货无从得知 |
| 56 多Agent | B | 建议整单取消，标准答案是换成最便宜款式 |
| 18 ×3 | C | 客户要“同款更换”，审查认为超出范围；标准答案是换成另一款式 |
| 77 ×3 | C | 客户要下新订单，审查认为超出范围；标准答案是换货 |
| 111 ×2、39、56三阶段 | C | 客户已要求人工，或认证未完成 |
| 62 三阶段 | C | 客户第一句是猜诗，审查认为无零售请求 |

## 解读

1. 事先设的门槛是强单的转人工能救回3次以上，实际是1次明确命中。**按当前审查指令，这个检查点没有通过。**
2. 放行的片段有共同原因。任务18、77：执行者没有先明确告诉客户“这件事办不了”，就直接转了人工；模拟客户的备选要求只有在被拒绝后才会说出。审查指令把“已解释过替代方案”当作放行条件，没有检查客户最后一个问题是否得到了直接答复。任务111、39：执行者主动提出“要不要转人工”，客户答应后就成了“客户明确要求人工”，审查指令规定不得推翻。
3. B类片段（32、56）说明：只要对话继续而不是转人工，客户很可能自己说出下一个要求。审查给出的具体建议不必猜中标准答案，关键是把“转人工”改成“告知限制并询问”。
4. 两种方法在真实难样本上仍然没有差别，与E1主结果一致。

## 限制

样本是已分析过的测试题；A/B为人工判定；“命中”只说明建议方向正确，不等于该题最终会成功；没有包含正确转人工的对照样本（E1主结果中为0/3误拦）。强单任务64（未行动）和4次认证阶段退出不在本样本内。

## 第二轮：修改放弃规则后再验（开发用途，不是效果证据）

2026-11-13。`review.py` 的审查指令改了转人工部分：只有在已明确告知客户该请求办不了、客户回应后仍坚持，且没有其他可办事项时才放行；客户最后一个问题未被直接答复时，要求先答复并询问；客户只是接受了执行者主动提出的转人工、而仍有可办事项时，要求先提出把可办的做完。写操作部分未改。内核离线测试36项通过。

同样20个片段，另加候选文件中全部7个“官方成功的转人工”作为对照，只跑独立审查，27次调用，费用$0.33，无重跑。结果在 `.runtime/e1-review/challenge-v2/`。

| | 第一轮 | 第二轮 |
|---|---:|---:|
| 20个过早放弃：要求修改 | 9 | 16 |
| 其中强单的6次 | 2（27、32） | 5（18、27、32、77、111） |
| 7个正确转人工对照：被要求修改 | 未测 | 3（36、70、100） |

- 强单仍放行的是任务39（认证未完成且客户主动要主管）。任务18、77的三阶段/多Agent片段仍放行，因为客户在那些对话里已主动要求人工。
- 新增的修改意见基本都是“明确告知办不了，并询问客户想怎么做”，任务77和111的建议直接指向标准答案里的换货和换款。任务18、32的建议不含标准操作，是否成功取决于客户随后是否说出备选要求。
- 对照中被要求修改的3条，原因相同：执行者没有先告诉客户遇到的问题就转了人工。这3题的标准答案都不要求转人工（7题中只有任务12要求，已正确放行），多问一轮不改变数据库结果，但会多一轮对话，并且客户的反应不可预知。按冻结标签这仍计为3/7误改，样本太少，无法给出可靠的误改率。

**限制。** 规则是看着这20个片段的失败原因改的，再在同一批片段上验证，结果必然偏乐观。“要求修改”不等于该题最终成功：修改意见只生效一次，之后取决于执行者和客户的后续对话。第一轮E1的172条保留集结果是在旧指令下得到的，不适用于新指令；写操作部分未改，但未重新验证。
