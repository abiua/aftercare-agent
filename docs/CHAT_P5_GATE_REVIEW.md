# P5 逐方案复核与程序门禁统计

2026-11-11。本轮实施计划；实际结果须在验收后补记。目标来自聊天改造第九项，不把客服采纳率、模型自信或程序检查通过当独立正确率。

## 评审流程和兼容性

沿用原有“先看冻结输入并封存初判→揭示候选→提交复核”流程。新增显式 `chat-blind-labels-v2` 请求，同时保存候选整体判断和逐方案的可以接受、不可以接受、无法判断。每个可用候选的每个方案必须恰好有一条标签；不可用候选不能虚构方案。

V1 请求、幂等摘要和历史记录保持原样，V1 不自动转换为逐方案标签。新标签只提交一次，不能看到统计后改判。评审页面不展示 Agent 分组、模型名称、程序门禁或审批结果。逐方案标签仍是揭示候选后的复核，须同时保留揭示前独立初判的证据。

## 程序门禁的来源

只使用可信登记时从原生不可变候选快照取得的 `checks`，绑定原快照 SHA、检查 SHA、原始 option ID 与盲态 option ID。映射留在私有登记记录，不能让复核员填写或通过请求伪造。旧映射缺少门禁时标记不可测，不从当前可变业务状态重新计算历史门禁。

## 分子、分母和排除

统计单位是方案，普通案和复杂案、不同 arm 各自报告，不把多个候选混成多数投票。

- 程序校验错放率：独立复核为不可接受且原门禁为 PASSED 的执行型方案数 / 独立复核为不可接受、且原门禁为 PASSED 或 BLOCKED 的执行型方案数。
- 程序校验误拦率：独立复核为可接受且原门禁为 BLOCKED 的执行型方案数 / 独立复核为可接受、且原门禁为 PASSED 或 BLOCKED 的执行型方案数。

退款和换发是执行型方案；补证、暂不支持、转人工及 NON_EXECUTING 不纳入上述门禁分母。UNDETERMINED、控制标签、无独立来源、输入不一致、缺候选、缺 V2 标签、缺原门禁或摘要不符均保留排除记录。分母为零时显示不可测，不显示0%正确或0%错误。

这些指标只描述原生程序校验；不代表反例 Agent 的整体核验能力、客服审批正确率或支付执行结果。复核员在候选揭示后评分也可能受影响，报告必须保留证据来源和流程边界，不声称绝对真值。

## 验收

旧V1请求与同key重放保持原摘要；初判/揭示前不能提交V2；重复/越界/漏选方案拒绝；V1↔V2同key冲突；阶段推进和用户权限不变。页面无门禁/arm泄漏，默认未选不能自动评价为通过，V1历史不强迫补填。

纯统计四格均有明确预期结果，并覆盖控制、未知、NON_EXECUTING、缺失、篡改和零分母。API/服务测试使用自动控制标签，只证明读写和隔离，不产生独立质量指标。实际独立人工标签尚未取得；不存在真人数据时必须保留不可测。

事实遗漏、政策适用/引用、补查前后纠错的逐项独立标签不包含在本轮V2中，继续作为未完成项，不用本指标替代。
