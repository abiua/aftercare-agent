# P4 聊天到调查验收

`scripts/verify_chat_p4_path.py` 使用独立的本机 5195 和 58357，状态文件为 `.runtime/offline-browser-demo-p4.json`。已有 5190–5194 环境继续由原验收使用。默认运行只检查本机 Docker、端口和状态文件，输出未绑定镜像的计划。提供两份经确认的完整镜像 ID 后，预检还核对标签所指镜像并输出计划摘要。显式执行需要相同镜像 ID、预检摘要和全新报告路径。

## 离线验收

1. 客户通过聊天发送问题和两张合成 PNG。上传请求只含文字、消息编号与文件。
2. 等待已登记的自动调查生成客服待核对候选。读取客服事件确认实际走程序分支。数据库核对自动请求与运行的绑定，并确认模型调用记录为零。
3. 客服读取同一事项的可关联原图并核对字节。逐张确认工单材料类型，比较聊天附件、关联记录和工单材料内容的 SHA-256，并检查幂等重放。客户读取或写入关联接口应收到拒绝。
4. 客服在独立工单材料审核接口确认合成材料。先验证关联操作本身没有完成材料审核，再检查材料审核后的实际资格。
5. 客服从聊天重新发起 P4 调查。检查新运行和实际路由，验证离线分支保留待人工判断状态。当前样例不生成可执行公开方案，因此不提交客户同意、财务审批或执行。业务账本须保持空。

合成 PNG 仅用于验证原图关联和字节一致性。离线验收无法证明视觉识别、真实模型调查、候选质量或生产资金执行。真实模型需另行冻结样本、实际请求次数和费用上限，核对默认传输和用量记录，并保留失败及未知结果。产生可执行方案后，客户确认、客服提交业务方案、独立财务审批和模拟执行才可作为后续验收动作。
