# 正式评测原生证据与执行接线契约

本契约补充[冻结与留出治理计划](HOLDOUT_FREEZE_PLAN.md)。当前本地登记已能锁存报告结构、验证预登记全集和记录暴露。下一步先接入测试库的原生验证证据，再让已冻结且已解锁的私有目录使用现有评测运行器。文中状态和入口是实现契约。

## 证据来源

| 来源 | 可证明的范围 | 正式验证状态 |
| --- | --- | --- |
| 本地报告或已导入报告 | 文件内容与登记摘要一致，报告声明的结构可核对。 | `UNVERIFIED_LOCAL_REPORT`。保留供审查，不能推进正式选型。 |
| 测试库原生实验及结果 | 由现有服务登记，计划、配置、案例、复核和运行状态可查。 | 原生实验可以进入核验。单有 `config.source=live` 或 `actual.observed_source=live_provider` 仍不能判定实际提供方观察。 |
| 测试库隔离调用账本 | 已准入尝试的身份、模型、状态、预算预留、用量和费用可与冻结结果对账。 | 已准入记录证明尝试获准。若缺少调用路径或提供方响应证据，保留 `NATIVE_LEDGER_ONLY` 或 `UNKNOWN`。 |
| 原生出站路径和提供方响应 | 由固定生产传输路径记录响应已观测，或记录超时、连接失败等不确定结果。 | 满足完整性条件的快照为 `NATIVE_VALIDATION_VERIFIED`。这表示本机可追溯验证证据，不表示账单或外部身份已核验。 |

现有运行器允许注入传输，且 `live_provider` 由结果是否包含调用记录推得。首版原生桥接需区分生产传输、测试替身、仅准入和已有响应。推荐在既有调用账本元数据中记录明确的运行来源和响应观察，标记仅由服务端固定生产路径写入。仅在生产响应返回后写入已观测标记，超时或连接异常保留不确定。提供方状态或响应摘要可用时只保留最小标识，省去原始响应、请求内容、密钥及私有地址。旧记录缺此字段时保留账本证据，不从旧别名、成功状态或非空用量猜测来源。

## 原生验证快照

### 入口与读取边界

增加正式登记 CLI 的 `validation-native --campaign <id> --record <file>`。输入字段为 `plan_sha256`、`experiments: [{group, experiment_id}]`、`selected_experiment_id`、`rationale` 和 `selection`。沿用已有 `HumanRecord`，拒绝客户端提交结果、模型尝试或来源验证字段。入口复用顺序 CLI 的测试运行配置和已有 tester 身份检查，再由 `EvaluationService` 核验。默认 `preflight` 仍只读本地锁存元数据，不读数据库、外部报告路径或留出明文。新命令只读数据库，无实验写入、Celery 投递、索引生成或模型调用。

`EvaluationService` 同时检查 test profile、数据库目标和当前有效的 tester。用同一个只读 `REPEATABLE READ` 事务读取所有对照实验、计划结果、采用的复核版本和隔离调用账本。调用账本由 `result_id` 派生 `eval_<UUIDhex>`，不采信 `actual.namespace`。缺隔离表、读失败或无法一一匹配的情况单列。现有补充用量服务使用独立会话，桥接可复用匹配规则与字段投影，读取仍需走同一快照。导入表、导出 JSON、无身份替身和 SQLite 测试环境没有升级来源状态的能力。

### 核验与锁存

1. **全集与配对。** 逐条件校验 `dataset_id`、`split=validation`、预登记 `(case_id, repetition)` 全集、每条 `quota.case_hash`、冻结 `expected` 摘要及实验汇总输入和参考摘要。拒绝重复、漏案、额外案和错划分。四个原始实验分别对应单 Agent economy、analysis、routed，以及预登记策略的三 Agent。B 组复用 A 组同一策略的单 Agent 实验 ID。各条件完整配置摘要分别匹配计划，去除该组指定变量后逐项核对控制条件。记录全部失败、超时、待复核、未执行。首版保留原始实验，禁止用补跑成功替换原条件的失败记录。
2. **实际运行配置。** 摘要从原生 `Experiment.config` 和结果证据计算。核验实际代码及锁、评分器、指标、注册表、模型 ID、策略、探针、并发、预算和索引配方与预登记值一致。注册表摘要覆盖所选接口、费率和超时。逐案校验已分配的调用／估算费用以及账本记录是否在额度内。仅有路径名或版本别名时，相关证据仍待补齐。
3. **政策与索引。** 验证配置锁存政策语料／选择规则、BGE 文件清单摘要、编码及检索参数、索引生成配方。隔离 runner 记录实际政策文档摘要和索引生成结果。混合检索需核对使用的编码版本和应建文档键。动态索引按各案的冻结政策范围生成，因此不同案例的索引内容摘要可以不同。相同案例在两个条件中使用不同政策、编码或配方则拒绝配对。冻结不把索引条数或目录名当成文件内容完整性证明。历史缺索引证明时返回缺项，无回填。
4. **调用账本。** 用 `(run_id, cycle, logical_id, ordinal)` 对照尝试。历史快照未存 `run_id` 时，保持无法精确匹配，不从独立 schema 中唯一的 `AgentRun` 猜测或补齐匹配键。每个对照条件需有实际生产路径响应证据。确定性门禁零调用可以是合法观察，依据冻结计划区分哪些案例应有模型尝试。未知、未配对、替身和缺审计保持原状态。晚到费用保留独立用量读数，原结果、指标和门槛继续使用冻结快照。
5. **选型与人审。** 数据库复核记录可证明现有账号保存了某版本的意见。金标、选型和发布仍要人提供具名说明和独立性依据。当前本地 `actor/source` 是 `UNAUTHENTICATED_DECLARATION`。证据快照验证和选型确认分别展示。未完成的质量、成本或人审条件不因来源核验而通过。

锁存 `schema_version`、campaign、验证计划摘要、实际实验 ID 和版本、结果与复核快照摘要、每个条件的实际配置／配额／索引摘要、账本观察计数和原因、来源状态、数据库读取时间及已采用的人审声明来源。输出只含定位标识、摘要和汇总，无候选明文、完整验证报告或原始 provider 响应。源数据完成后发生复核或用量变化时，不覆盖原快照。冻结命令用当次原生快照和人确认的草案摘要。若实际采用新版复核或晚到用量，应生成新验证记录并重新确认，旧证据继续可查。

继续使用 `FORMAL_VALIDATION_MISMATCH` 拒绝配置或配对冲突。来源、账本或索引证据缺项时，可以保存原生快照的缺项及原因。正式冻结继续返回 `FORMAL_VALIDATION_SOURCE_UNVERIFIED`，直到来源核验通过；报告里的失败和 `UNKNOWN` 仍参与正式选型判断。

## 私有目录执行接线

首版沿用同步 `inline` 驱动。正式入口只接受已冻结、已登记解锁且 `NATIVE_VALIDATION_VERIFIED` 的运行计划。单一配置只用于首批工程分步验收。完整交付必须完成正式 A／B 两组对照，保留每组失败与 `UNKNOWN`。全部条件、顺序、重复和预算均在解锁前登记。当前受控合成解锁留在 `purpose=fixture`，不能在正式入口转为真实来源。

| 边界 | 接线约束 |
| --- | --- |
| 目录与参考 | 通过内部目录适配器提供 `load_cases` 和 `load_references`，在同一打开视图内复核候选、清单、案例、参考和材料输入。冻结前不访问私有目录，解锁后也不把路径或明文挂到普通数据目录。复用现有合成材料生成，若需私有图片则必须有清单摘要和明确适配器。Agent 继续只见正常业务上下文。 |
| API 与驱动 | 复用现有测试守卫、tester、隔离 schema、检查点、评分、进度和支付替身。正式目录仅能经内部构造路径注入。普通 API、旧 CLI、公共 `v0.2` catalogue 与 Celery 均无法创建或领取此类 `inline` 任务。普通补跑入口拒绝正式实验。 |
| 稳定身份 | 由冻结 SHA-256 和条件键推导稳定实验 ID。创建在数据库事务内检查唯一实验主键并保存原冻结绑定，重复命令或更换 tester 时回读同一实验。普通幂等键仍使用现有 actor/scope 边界，正式跨操作员唯一性不依赖该键。若同一标识的冻结配置不同则拒绝。结果继续使用现有实验／案例／重复唯一约束。 |
| 批次与预算 | 解锁前为各条件固定最大调用和费用额度，按整数微美元检查总和不超过全批上限。复用现有 `_allocate`、逐案配额、调用准入、原 `ModelAttempt` 审计和模拟支付。预算不可从失败、未使用或未知条件自动转移。首次领取持久保存，晚到或不明费用保留保守预留，不创建第二个同条件实验。 |
| 配置漂移 | 创建、恢复和首次付费准入前比较实际代码／依赖、模型注册、政策、索引配方、冻结输入和预算。恢复加载已登记的目录和冻结清单。有效身份撤销、文件改变、读取异常或证据不符时停止后续调用，保留原结果。需要改变冻结条件时使用新登记与符合未见资格的数据。 |
| 中断与报告 | 恢复同一实验 ID，使用现有租约和 `WORKER_INTERRUPTED` 处理在途结果。已有请求状态未知时按原审计核对，不为补成功而重放。记录冻结 ID、实际实验和结果、失败、未知、人工复核及技术门槛。正式发布仍等待人对具体报告的独立批准。 |

## 验收矩阵

| 检查 | 可验收结果 |
| --- | --- |
| 来源与授权 | 真实 test PostgreSQL 只读核验原生实验，app／非 tester 拒绝。仅导入 JSON 或注入模型替身无法得到 `NATIVE_VALIDATION_VERIFIED`。缺生产响应标记的历史实验得到明确缺项。 |
| 一致快照 | 原生实验、复核和隔离调用证据在同一事务读取。并发晚到用量或新版复核不会造成混合版本。保存后读回原结果、指标及门槛完全一致。 |
| 全集与版本 | 同源原生实验的计划配对通过。漏案、换重复、换模型、预算、代码、索引或私有文件任一漂移时拒绝继续。使用受控样本验证拒绝路径。 |
| 正式接线 | 合成候选在测试夹具走完整冻结绑定、数据库稳定实验 ID 和预算恢复。并发启动或更换 tester 均只有一个实验。未知请求不重发，不触达 app 数据或真实支付。 |
| 正式结论 | 另行以真实验证实验、实际新候选、人审与实际正式报告核验。零模型或注入测试记录只作为工程证据。 |

实现顺序为先交付只读原生快照和可信来源判定，再接入目录、稳定实验 ID 和预算。当前已实现原生账本快照锁存入口，并完成实际 PostgreSQL 一致性快照验证。新增尝试已记录默认/注入同步/流式路径与响应观察；根代理于 2026-11-10 完成四次真实 API 验证和独立 SQLite 账本回读，估算费用合计 0.000396 美元（reports/transport-provenance-root-review.json）。政策和索引内容证据已实现，35 项组合回归通过，真实 BGE/PostgreSQL 检索核验仍在进行。入口目前仍保留 `NATIVE_LEDGER_ONLY`，不因少量合成提示验证而自动批准正式质量选型。完整来源状态提升条件、私有目录执行接线与独立人审仍待完成；未开启正式留出。
