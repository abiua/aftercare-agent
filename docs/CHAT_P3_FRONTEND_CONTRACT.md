# P3 聊天方案与复核界面

本页记录前端接线。决策来源、授权、政策校验与失效条件沿用服务端。[P3 服务契约](CHAT_P3_CONTRACT.md)

- 会话读取提供可选的 P3 能力标记。标记缺失时，P1/P2 会话不请求决策路径。客户继续使用公开会话数据，不读取内部运行环境。
- 客服读取当前事项的候选、最新处理记录和精确候选引用。页面区分 Agent 原始候选和客服修改稿。原候选可以通过受授权的历史读取回看。每项显示商品范围、金额或数量、依据、程序核对结论和未决问题。
- 客服采纳、修改、拒绝、补证或接管均填写理由。采纳绑定选项，修改提交结构化方案及明确已解决的原问题。提交附候选 ID、版本、摘要和当前最新处理记录 ID。冲突刷新后重新核对，保留旧候选。客服启动入口由服务能力提供。
- 客户读取当前公开方案，只展示订单、商品、退款金额或换发数量、可公开依据及确认状态。接受、拒绝或请求修改绑定精确方案引用。客户确认仅表示对本方案的意见，后续由客服和审批流程处理。
- 客服和客户分别使用经角色授权的读取路径。方案与内部候选都用服务端回传的确切版本。未成功写入时保留当前输入。公开界面不加载内部候选、客服理由或运行轨迹。

## 接线路径

以下路径均以 `/api/conversations/{conversation_id}/decisions` 为前缀。会话详情的 `features.chat_decisions` 为 true 时启用。

| 角色 | 路径 | 用途 |
| --- | --- | --- |
| 客服 | `GET /` | 读取当前候选及最新复核摘要 |
| 客服 | `GET /history/{snapshot_id}` | 回看本会话历史事项的旧候选 |
| 客服 | `POST /run` | 申请启动本事项的方案调查，后台异步产出 |
| 客服 | `POST /review` | 保存绑定到具体候选版本的复核和理由 |
| 客户 | `GET /offer` | 读取当前公开方案及答复状态 |
| 客户 | `POST /offer/respond` | 针对具体公开方案版本提交意见 |

写入沿用现有表单的幂等键。打开同一表单且提交内容相同时，网络失败后重试沿用同一个键。页面通过会话刷新和定期读取发现新候选或新方案。客服修改可调整现有候选的退款金额、换发数量和说明，并逐项确认已核对清楚的事项。

客服读取的 `latest_review.program_check` 单独展示复核时的程序结论。候选上的 `checks` 保留生成当时的结论。当前公开方案已有客户回复时，客服可读该方案版本、回复和客户提供的说明。要求补证可提交结构化 `evidence_gaps`，客服内部复核理由仍保留在内部。切换订单或事项时，界面清除上一范围的方案和待提交表单，并等待当前范围读取。

同一方案已接受后，客户仍可撤回同意或提出修改诉求。两种操作都绑定原方案引用并替代先前同意。提交后原方案不再提供接受操作，重新同意需要客服提出新方案。
