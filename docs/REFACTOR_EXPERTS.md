# 阶段5：按需专家与六组配置

2026-11-13。全部为离线验证，本阶段没有付费调用。

## 实现

`agent_kernel/experts.py`。专家只在程序信号命中时调用，无信号时调用数为零。

| 信号（程序从对话记录判断） | 专家 | 问题 |
|---|---|---|
| 客户提出带条件的选择（最便宜、最大、预算内等），且对话里已有商品记录 | 事实对账 | 哪些可选项满足客户的条件 |
| 客户在消息中点名了两个及以上已查到的订单 | 事实对账 | 每个请求对应哪个订单、哪件商品、当前状态 |
| 客户点名某订单并要求某操作，而订单状态不满足该操作 | 政策分析 | 是否可行，政策允许的替代做法 |

- 认证完成前不触发。每个信号在一次对话中只触发一次，每次对话最多3次专家调用，结果缓存后在后续步骤继续提供。
- 专家在独立上下文中工作：只收到白名单公开消息和一个具体问题；政策专家另收到政策原文。不带执行者提示、内部推理或旧审查结果。
- 输出由程序核对：候选项的编号必须出现在工具结果里，政策引用必须是政策原文，核对不过的条目直接丢弃并记录数量，不做修补。
- 结果以系统消息附在执行者下一步的输入里，注明是数据而非指令，需对照工具结果核实。专家不替客户做选择。
- 专家出错、超时或输出格式无效时，返回空结果并记录原因，执行者照常继续。
- 读工具：服务支持注入读端口，带范围检查（仅允许读工具、已认证用户、其名下订单）和次数上限，越界请求被拒并记录。**官方评测适配器不注入读端口**，专家只分析对话中已有的记录，保证所有工具调用都留在官方轨迹里。读端口留给阶段6的产品适配。

内核现在要求M1/M2必须装配专家，缺失时在调用模型前报错。官方适配器已装配。

## 六组配置

S0/S1/S2/S1c/M1/M2在离线替身下各走一步，核对每次调用的角色和模型：S1c和M2的执行者是deepseek-flash，审查、自检和专家都是gpt-6.1-sol；只有M1/M2调用专家；S2走自检、M1/M2走独立审查。专家调用计入每题Agent预算桶。

## 未验证与限制

- 专家没有用真实模型调用过，输出质量、对执行者是否有帮助都未知。按计划它不单独设主张。
- 信号是关键词和订单号匹配，会漏掉措辞不同的情况，也可能误触发；触发率是在已见过的测试题对话上统计的。
- “客户陈述与工具结果不一致”只实现了订单状态这一种；图片证据信号属于产品环境，留到阶段6。
- 审查Agent不能主动请求专家（审查输出里的requests字段未启用），因为改审查指令会使刚做的验证失效。
- deepseek-flash的工具调用能力仍未验证，留到阶段7的接线检查。
