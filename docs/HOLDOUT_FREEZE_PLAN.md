## 操作顺序

1. **登记新留出候选。** 由保管人准备尚未给开发或选型人员读取的本地目录，预先记录数据标识、清单摘要、数量、三意图分布、来源和场景族检查结果。沿用三意图各 10 个独立案例的目标，任何调整在冻结前注明。原文、译文、同模板改写和可识别的近重复不跨集。保管人可以让独立审核者查验金标，并登记这类受控接触。开发工作区、镜像、普通案例列表和公开报告不含正式输入或参考。无需新增基础设施，保管人负责记录共享边界和任何提前接触。
2. **登记验证选型。** 先固定候选矩阵、数据划分、质量口径、硬规则和成本，后读结果。验证 A 固定单 Agent 比较 economy、analysis、routed。验证 B 固定一种预登记策略比较单 Agent 与三 Agent。若检索策略参与选型，在验证集上另做同案配对比较。可以用已暴露的 `v0.2` 验证数据，报告注明来源。记录实验 ID、配置和报告摘要、样本量、失败、超时、人工复核、成本未知及比较结论。仅有离线结果或开发集成绩时，正式真实模型选型仍待完成。
3. **确认并冻结。** 有权人确认入选配置、验证结论和技术门槛，留下姓名或身份、时间、来源和所确认的摘要。冻结清单同时绑定新留出的登记清单与执行矩阵。指标、预算、模型、代码或参考发生变化后，需要新的冻结记录。若留出内容已经暴露，则换新候选，原数据及报告保留。
4. **登记解锁再执行。** 保管人核对冻结清单，把已登记目录交给正式运行者。入口先记录交付，再读取内容。读到明文即记录已解锁，读取途中中断或暴露无法确认时如实记录。正式计划随后以明确的运行操作执行。冻结前接触了内容的选型人员必须登记暴露，该候选不能再作为正式未见集。
5. **复核并报告。** 独立审核者按准确的案例、事件和周期核对事实、引用、处理意见与实际结果。独立金标和运行后结果复核分别保留。技术门槛输出 `PASS`、`FAILED` 或 `INCOMPLETE`。技术 `PASS` 仍等待有权人对确切报告和复核版本作出发布决定。没有实际人工记录时保持待确认。

## 实现契约

先交付小型本地登记模块和独立 CLI，再接入现有顺序评测服务。普通实验、普通 CLI、原报告与原参考均保持兼容。

| 边界 | 最小契约 |
| --- | --- |
| 本地记录 | 建议按 `.runtime/formal-evaluation/<campaign_id>/` 保存候选登记、验证登记、`freeze.json`、暴露事件和现有实验 ID 引用。冻结文件一次写入。暴露事件只能追加，带时间、操作者、角色、原因和关联摘要。正式目录只保存需要的文件。数据本身保留在保管人登记的本地目录。 |
| 候选登记 | `dataset_id`、清单 SHA-256、声明的分布、来源与分组审核引用、保管人和时间、已知暴露。候选清单约定案例和参考文件摘要。登记阶段不读取候选明文。直接拒绝 `v0.2`、已知旧文件摘要和已登记为提前暴露的候选。仅改名不能改变历史资格。未知接触和同源改写需人工核对。 |
| 验证登记 | `experiment_id`、`dataset_id/split`、配对角色、实际 `source`、配置摘要、报告或复核快照摘要、覆盖与证据状态。使用现有比较规则检查同案和同重复编号，只改变预声明因素。冻结前重新读取这些摘要。两组验证报告及结论可追到实际失败和未知。 |
| `freeze.json` | `campaign_id`、候选清单摘要、验证报告及选择理由、代码与锁文件摘要、Prompt 和路由实现或配置摘要、实际模型 ID 与注册摘要、检索模式和 BGE/索引版本或内容摘要、政策和评分定义摘要、阈值正文、每条件固定样本与重复编号、每案和全批调用／费用上限、人工确认来源。代码指纹已覆盖源码内的 Prompt 等组件时直接复用。动态索引绑定语料、生成配置和模型版本，并记录实际生成状态。 |
| 只读预检 | 建议 `python -m aftercare.evaluation.formal preflight --campaign <id>`。默认检查登记、验证和冻结结构，以及当前可检查的运行配置。仅显示状态、数量、摘要和不满足项。预检不打开留出内容、不创建实验、不调用模型。已有验证报告可以通过保存的只读导出核对。 |
| 明确解锁 | `unlock --campaign <id>` 只在冻结确认和候选未提前暴露时接受。先追加解锁交接，再在同一操作中校验登记清单及文件摘要、划分和案例完整性。若结果不明，记 `EXPOSURE_UNCERTAIN` 并禁止按未见执行，直至人工核对。常规入口不挂载或枚举候选目录。 |
| 明确执行 | `run --campaign <id> --execute` 只接受已经登记解锁、内容和运行指纹匹配的冻结计划。只走测试 profile 守卫。通过私有目录适配器和内部入口复用 `EvaluationService` 的计划持久化、逐案运行、评分、审计和报告。普通 API 的 `v0.2` 请求模型不开放任意目录。运行器只向 Agent 提供正常业务上下文，参考供评分。 |
| 批次与预算 | 用冻结摘要和条件键推导稳定幂等键，记录对应现有实验 ID。重试入口先读账本，恢复原实验或返回其状态，不能重新建同条件。多个预登记条件的额度之和须在冻结总上限内，每案和每次调用仍走现有准入。未知调用保留记录并按现有保守额度计入。普通补跑入口不能绕过正式配额。单一入选配置可用于首批工程验收。正式交付须预登记两组 A／B 对照、固定交错或分块顺序，保留各组失败和未知。 |
| 人工记录 | 金标登记绑定 `dataset_id`、`case_id`、案例与参考摘要、独立审核者、时间、结论和出处。发布记录绑定冻结摘要、正式报告摘要、所用复核版本、批准或拒绝、操作者与时间。参考自带的 `VERIFIED`、用户名或自动技术通过均不能替代真实的人类记录。 |

最低状态为 `REGISTERED` → `FROZEN` → `UNLOCKED` → `EXECUTING` → `COMPLETED`／`FAILED`／`INCOMPLETE`。另存 `EXPOSED_BEFORE_FREEZE`、`EXPOSURE_UNCERTAIN`，以及解锁后的实际访问记录。已接触明文的候选始终有暴露历史。`UNLOCKED` 表示对冻结后的首次正式执行有记录，不能用于之后重新选型。建议用本地文件锁序列化状态变更，结合现有实验幂等和租约恢复处理进程中断。现有测试 profile 和人员身份可复用，交接与独立性由人员记录核对。

## 门槛与验收

正式汇总复用现有指标，显示适用分母、独立案例数、各次尝试、失败、超时、未执行、未知和实际费用。金额、归属、审批和幂等等硬断言按冻结的适用案例和事件核对。明确违规优先失败，缺少预期证据、金标或人审保持未完成。费用账本缺证保持未知。验证集用于调整门槛，正式留出结果一旦可见，同一数据只能作为已暴露的后续分析。

| 验收 | 通过条件 |
| --- | --- |
| 兼容与来源 | 旧 `v0.2` 仍可通过普通入口运行，原报告可读。旧版本、旧摘要及提前暴露记录均无法进入正式未见。 |
| 验证与冻结 | 登记报告与实际输入、同案配对和配置一致。缺选型结论、人工确认或门槛时无法冻结。源报告、候选清单、配置、阈值或预算变化时拒绝原冻结。 |
| 预检与暴露 | 预检不读私有候选文件。未冻结执行和解锁被拒。冻结后的合成包可解锁，并验证明文读回前已有交接记录。中途失败保留暴露状态。 |
| 运行与预算 | 同一正式条件重复启动或进程中断后恢复，仍对应同一实验 ID。配置漂移无模型调用。费用不明不被填为零。条件和补跑不能越过冻结预算。 |
| 评分与发布 | 对可手算的合成样例验证缺证据、违规、完整技术通过。技术通过不产生发布批准。真实未见结论须同时有新候选的实际交接、真实验证选型、正式尝试和独立人工记录。 |

实现分三步。先交付候选、验证和冻结清单的校验与只读预检，再用合成包零模型验证暴露状态和现有账本接线，最后由人登记正式候选和确认记录。当前是计划，尚未实现上述正式入口，也未运行或修改现有评测。
