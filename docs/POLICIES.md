# 模拟售后政策 v1.0

这 12 条规则适用于本项目虚构订单和离线案例。所有金额以整数分表示，所有时间以带时区的 ISO 8601 表示。规则自 `2026-01-01T00:00:00+08:00` 生效，数据观察时间为 `2026-11-10T12:00:00+08:00`。规则仅供项目模拟使用。

| 编号 | 规则 | 判定口径 |
| --- | --- | --- |
| `POL01` | 本人订单 | 核验请求人与订单所属客户一致后，才可返回订单详情或受理售后。 |
| `POL02` | 实付核验 | 退款前，支付状态须为 `CONFIRMED`，有付款时间且实付大于零。付款不明时先核验。 |
| `POL03` | 未发货取消 | 已付款且未发货时，执行前复核履约状态。确认未交运才可取消，并按剩余实付办理退款。 |
| `POL04` | 已发货拦截 | 已发货时可申请拦截。物流明确确认成功后才可取消并进入退款审核。待确认或拦截失败时保留当前履约状态。 |
| `POL05` | 签收退货时限 | 只对 `returnable=true` 的商品受理普通退货，自 `delivered_at` 起 168 小时内申请，含恰好 168 小时。每行商品独立判定。 |
| `POL06` | 损坏补证 | 损坏售后须提供商品损坏照 `ITEM` 和外包裹照 `PARCEL`。资料未齐时记录缺项并请求补充。 |
| `POL07` | 签收后退货退款 | 普通退货获准后安排寄回，收到退件且验货通过后才可提交退款审核。 |
| `POL08` | 重复退款 | 同一退款请求已有确定的处理记录时，查询并返回原记录，复用原流程。 |
| `POL09` | 部分退款金额 | 先确认已有独立核准的售后处置或商家补偿决定，再核验金额。每行上限为行实付减行已退款，合计还须在订单剩余实付以内。部分退款只计商品金额。明确请求金额超限时说明可退金额，并请求确认更正。 |
| `POL10` | 高额退款审批 | 拟执行的单笔退款超过 `50000` 分时，须先获得人工审批。恰好 `50000` 分符合金额阈值要求，可继续检查其他条件。 |
| `POL11` | 商品质保 | 有质保的商品按 `warranty_days` 自签收起计时，含期限终点。满足条件时可提交质保服务审核。普通退货资格和质保资格分别判定。 |
| `POL12` | 退款执行结果未知 | 执行超时或结果未知时，按原 `idempotency_key` 核对外部结果，确认前保持待核对状态。 |

## 多条规则同时适用时

1. 先核验本人订单。未通过 `POL01` 时结束售后判定。
2. 同一请求已有执行记录时，未知结果按 `POL12` 优先核对，已知记录按 `POL08` 查询并复用。新请求才进入新的退款资格判定。
3. 新请求按 `POL02` 核验支付。已付款但未发货按 `POL03` 复核。复核发现已交运时改走 `POL04`。已签收时根据商品资格与申请时点走 `POL05` 和 `POL07`，或根据商品质保期走 `POL11`。涉及损坏的申请还须满足 `POL06`。质保服务审核本身不产生退款执行动作。
4. 对可进入退款审核的申请，先核验部分退款是否已有经核准的售后处置或商家补偿决定，再按 `POL09` 核验金额。`POL10` 的人工审批独立适用。执行时继续使用同一业务请求的幂等键。

## 基表的金额与履约状态

- 每行原价为 `quantity × unit_price_cents`。订单 `subtotal_cents` 是各行原价之和。优惠按原价比例分到各行，零头按小数余数降序分配，同余数按订单行顺序分配。
- 行和订单均提供 `discount_cents`、`payable_cents`、`paid_cents` 和 `refunded_cents`。应付等于原价减优惠。已确认付款时实付等于应付，未付款时实付为零。订单各金额字段等于对应行金额之和，已退款受实付约束。
- 基表订单履约状态为 `UNPAID`、`CANCELLED`、`PAID`、`SHIPPED` 或 `DELIVERED`。基表 `CANCELLED` 表示未付款即取消。签收订单可含历史部分或全额退款，履约状态仍为 `DELIVERED`。有交运时间的订单各有一条物流记录。
- 基表已退款金额是观察时点的模拟余额。审批、退货验货、退款执行及核对过程由独立案例输入描述。
