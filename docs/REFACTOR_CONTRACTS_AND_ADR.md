## 边界契约

定义位于 `backend/src/aftercare/agent_kernel/contracts.py`。

| 契约 | 产生/消费 | 字段与失败行为 |
|---|---|---|
| ToolPort | 环境适配器提供、内核调用 | 工具名称、读/写/认证/转人工类别、参数schema；未知工具和越界请求拒绝。只读端口不得代替提交端口执行写操作。 |
| StepProposal | 执行者生成、护栏和提交端口消费 | 客户文本、工具调用、参数来源；private_context仅供执行者和S2，独立审查剔除。缺来源不是自动补造证据，交审查核验。 |
| GuardResult | 程序产生、内核及审查消费 | allowed、反馈、规则ID、确认事实。硬规则失败最多重新生成一次；仍不合格不能直接执行。 |
| ReviewResult | 审查或自检产生、内核消费 | allow/revise；revise必须有具体问题和下一步。无“否决并转人工”动作。无效格式、超时、预算不足默认放行并记录原因，但仍经过程序护栏与产品人工审批。 |
| ExpertRequest/Result | 审查/程序提出，专家返回 | 单个问题、已认证用户/订单范围、读工具白名单及上限；主张及证据、候选条件/价差、政策引文、未解决项。越界不查询，超预算返回已获取证据和停止原因。 |
| TraceEvent | 模型端口/内核产生、审计消费 | 显式角色、阶段、模型、输入哈希、输出、用量、费用、耗时、失败原因；未知成本为null而不是0。 |
| CommitPort | 内核调用、环境实现 | 官方提交执行工具；产品提交只生成候选快照，审查结果随快照保存。客户确认、客服审核、财务审批和账本执行不合并。 |

## 核心不变量

执行者是唯一客户发言者；独立审查不读执行者私有推理、旧审查意见或专家中间讨论。一次性反馈只进入紧邻的重新生成。重新生成后的提议依然受硬规则约束，不再递归调用审查。

所有执行者/自检/审查/专家共用48次Agent调用限额；用户模拟与官方裁判独立记账。角色从调用参数确定，不能从模型名猜测。模型端口负责预约和结算；缺预算不调用模型。重试不是新的免费预算。

专家不改订单，不替客户选择；产品深度调查结果不自行升级成可信事实。新内核图版本 `aftercare-kernel-v1` 与旧图检查点隔离。官方评分、任务目标、结局标签不进入模型上下文。
