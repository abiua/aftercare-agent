# 售后协作工作台演示

目标时长 **4 分 20 秒**。2026-11-11 首轮同案离线浏览器业务链路已完成，实测 **871.64 秒（约 14 分 32 秒）**，3–5 分钟计时未达标。未录制视频，最后的历史恢复／对照展示未执行，完整台本仍待验收。

## 开始前

- 由集成负责人确认独立测试工作台 <http://127.0.0.1:5187> 可用。页面应显示「当前环境使用离线策略」。同时确认 API 和任务进程均禁用模型，且任务进程可以领取测试任务。体验入口 5186 当前可能调用真实模型。
- 在三个浏览器标签分别以客户、客服、审批人登录。第四个标签可提前登录测试员并打开版本对照。凭据从本机私有文件读取，录制从登录完成后开始。
- 客户选择本人已签收、已确认付款且仍有可退款额度的模拟订单。确认该订单范围未办过破损处置，并留出商品照、包裹照各一张明确标记的合成图片。排练消耗的订单另换一笔。准备一个已完成的历史工单及两份现有对照报告，用于只读备选。
- 启动秒表时停在客户工作台。前几个环节以同一订单、同一工单、同一助手运行为主线。切换角色时从当前标签复制工单详情地址，粘贴到对应已登录的标签。

## 实测记录

- 记下实际总时长和各段起止时间。分别记下当前环境、模拟订单、工单、运行、审批及回执标识，便于回读。
- 同案续跑无草案时，以页面显示的原因说明当前阶段。执行显示未知时，指出原记录与「核对执行结果」入口。遇到排队、角色操作或账本异常，保留现场，切换到已完成的只读案例讲解，并标明哪几步属于历史回放。
- 只有完整现场链路在 3–5 分钟内结束并能回读，才记本轮计时通过。此前已有真实业务闭环和浏览器财务流程，可用于排练与备选，不计为本台本的完整计时记录。[业务闭环](../reports/business-full-flow.json) · [浏览器模拟财务闭环](../reports/browser-financial-flow.json) · [人工标注表单只读验收](../reports/browser-review-annotations.json)

## 2026-11-11 首轮现场结果

独立离线工作台 5190，订单 O0182；客户建单、客服启动三 Agent、缺照暂停、客户两次选图上传、客服材料审核、同一运行恢复、手工提交 178 元方案、审批角色批准、客服模拟执行、客户查看成功回执均通过真实页面完成。数据库确认 1 个工单 RESOLVED、1 个运行 COMPLETED/cycle1、2 张材料、1 次材料审核、1 个方案、1 次审批、1 次执行、1 笔模拟支付，模型尝试为 0。

计时包括工具协调和用户选图等待，没有扣除耗时或重置。合成图和脚本审核不证明真实破损，三种角色由同一操作者测试不算独立质量评审。离线助手没有填退款金额，客服按模拟客户诉求手工填入。7 段浏览器捕获与独立账本回读见[报告](../reports/browser-full-offline-demo-20261111.json)。

另发现实时状态推进后，旧成功提示仍可能显示“等待人工审核”或“等待审批”；最终状态和回执正确。源码已将这两条提示改为确认提交并引导查看当前记录，避免旧通知继续声称正在等待；本地及容器构建、[托管检查](https://github.com/abiua/aftercare-agent/actions/runs/42950757716)通过；5186已部署，HTTP页面资源与本地构建逐字节一致，其余六个应用容器未重建。部署后浏览器视觉复验未另做。[部署报告](../reports/deployment/confirmation-app.json)。
