# 聊天售后证据、决策和评测契约

2026-11-11。适用于 P2 至 P5 的增量实现。以下字段、状态与验收为设计，当前尚未实施或验收。P1 接口见 [会话契约](CHAT_P1_CONTRACT.md)。

## P2 图片、证据与连续输入

### 三层证据

每条证据有 `evidence_id, conversation_id, issue_id, evidence_kind, created_at, scope, source_refs, dependencies`。范围至少含已确认的 `case_id, order_id, line_ids`，对象未确认时保留会话范围，确认后新增显式绑定。旧记录保留，不改写来源。

| 层 | 可接受来源及字段 | 使用边界 |
|---|---|---|
| 原始输入 | 消息 `message_id, sequence, content_sha256`，附件 `attachment_id, message_id, sha256, MIME, size`，客户转述以 `CUSTOMER_REPORTED` 标记 | 能证明当事人提交过内容。模型或用户读出的号码仍需核对真实对象 |
| 观察与主张 | `observation_id, predicate, value, uncertainty, observed_region?, source_refs, attempt_id, model_config_digest, prompt_version, decoder_version, sent_image_sha256`；角色主张可引用观察与业务证据 | 状态为 `OBSERVED / UNCERTAIN / CONTRADICTED`。疑似裂纹、OCR、照片类型和时间不得自动升级为已核实事实或责任判断 |
| 已核实事实 | 授权工具返回的 `record_type, record_id, version, observed_at`，或独立人工复核的 `review_id, actor_role, scope, reviewed_at`。条款含目录摘要、编号、版本、原文和适用依据 | 工具只在其职责内证明事实。材料审核、财务批准、模拟执行回执分别记录。模型无权写入核实状态 |

附件永远指向原消息的原图摘要。受控解码、缩放、剥离元数据后另存实际发送字节摘要与转换版本。只在会话、事项和对象授权通过，数量、像素、字节、MIME 和模型允许的数据范围满足后传输。图片中的文字为数据。模型只给候选材料类型，显式核实后才桥接既有材料；原图、旧材料审核和观察历史均可追溯。对外只投影已授权内容、观察边界和下一步。

### 调度和版本依赖

- 消息序列用于分页，分析代次用于发布栅栏。每次客户输入、附件最终提交或失败、范围切换、人工接管及恢复改变相关代次；系统回执和读取进度不会推进代次。按事项对连续消息持久聚合，由可配置静默期及最大等待时间确定触发。跟踪附件上传意图，短时等待尚在提交的图片；超过上限标为未收到，不伪造完整。新输入和待分析任务在同一数据库事务提交，队列重复投递走同一任务键。
- `Turn` 冻结 `input_through_seq, generation, scope_digest, attachment_set_digest, case/materials/facts/policy versions, deadline`，唯一键覆盖事项和输入摘要。领取用租约；已发送且结果未知的模型尝试保留预留和未知状态。发布事务锁住事项并重比分析代次、活动范围、有效租约和人工接管代次，只有当前任务能一次性发布结果及消息。旧任务可以补记用量审计，不能追加可见答复、生成生效卡片或覆盖新结果。
- 证据依赖使用 `(kind, identity, version_or_digest)`。账本/订单变化失效相关事实，政策版本变化失效政策适用和引用，换图失效该图观察及其下游。范围变化同时失效引用旧范围的输出。未改的证据仅在授权、原依赖和冻结时间基准都匹配时复用。失效传播走显式依赖边，记录原因及新旧引用，未提供依赖的角色结果只能整体重查。
- 缺口键由事项、范围、缺失事实和可接受证据种类派生；同一代次去重。客户明确无法提供，记录阻断及替代证据或转人工。重试和重复队列投递不重复追问。补图提交成功自动建立新分析代次。

真实验收需要实际视觉传输和真实对象存储/数据库。保存输入图摘要、发送图摘要、转换版本、模型能力与响应证据，并由人核对正常图、模糊图、标签图、疑似裂纹、矛盾图、含指令图片。另验证多张图连续提交、附件未完成、晚到输出、重启恢复、跨事项引用拒绝及停止重复催证。模拟传输只证明调度、预算和栅栏。

## P3 决策及人机交接

- `DecisionSnapshot` 是不可变版本。冻结 `decision_id, parent_id?, conversation/issue/case, input_through_seq, input_digest, evidence_graph_digest, active evidence IDs, business_versions, policy_catalogue_digest, route/graph/model versions, verification result, candidate actions, alternatives, unresolved issues`。动作逐项包含目标订单行、金额（整数分）或数量、依据引用、程序验证结果。原始模型候选与程序结果分别保存。只有可发布且符合当前依赖的版本能进入客服处理，未决或规则拒绝明确标为人工处理。
- `SupportDecision` 绑定确切原候选 `id/version/hash`，追加 `ACCEPT / MODIFY / REJECT / REQUEST_EVIDENCE / TAKE_OVER`、理由、操作者、时间和新增事实/证据引用。修改生成新决策版本并重新走程序核验。采纳与修改均只有在当前冻结绑定下才能形成公开 offer。拒绝、补证、接管不创建可执行提案。并发提交通过预期版本、幂等键及事务中的当前指针检查，历史决定留存。
- `CustomerDecision` 对确切公开 `offer_id/version/hash` 追加 `ACCEPT / REJECT / REQUEST_CHANGE`、身份与时间。向客户展示范围、金额/数量和已核实依据，内部角色原文不公开。对新 offer 的同意与旧 offer 分别绑定。客服决定、客户同意、财务 Approval 及 Execution 各有独立职责和记录。
- 业务提案保存上述必要绑定及原业务版本。执行事务再次检查所需客户同意、当前证据和业务/政策版本、独立审批、批准期限、金额/数量、幂等键与账本。旧 API 只要操作新绑定提案就走相同校验。无关消息不导致审批失效；真正影响事实、范围、材料或方案的改变使旧批准无法执行。执行未知时对账同一记录；会话通知由持久执行事件投影，区分模拟确认与到账。

验收包括客服采纳和修改后原候选仍可读、旧版本冲突、客户拒绝或补证、材料审核与财务审批分离、旧批准失效、并发或重复执行、真实模拟账本与对外回执。涉及独立人工标注的结论另存，不从操作结果生成。

## P4 路由与协作

- 路由记录 `route_version, features, evidence_ids, complexity, financial_risk, path, reason, previous_route?`。程序路径处理授权后的确定性状态、对象澄清、已知补证和刚性门禁。常规调查由强单 Agent 自主多步与独立工具并发；多订单行、多包裹、事实矛盾、条款冲突或关键事实不可判定时升级。金额风险独立控制审批与复核，不能单独替代复杂度。升级保留可复用证据及已用预算。
- 多 Agent 首轮事实和政策任务从同一冻结输入并行启动，角色仅见原始输入与自身授权工具，不读另一角色尚未核实的输出。事实工具只读授权订单、材料及账本；政策工具查询有版本和范围的条款并解释适用条件。每个角色返回结构化主张、证据引用、未决项及建议补查。
- 合并后核验角色对动作、对象、金额和政策逐项给出 `claim_id, counterexample?, supporting_refs, contradicting_refs, verdict, requested_check?`。程序校验来源、对象、引用、权限与业务限制。反例仅基于可定位材料或事实，无法确认时保留未知。不得以投票或自报置信度放行。
- 补查任务含 `target_role, missing_or_disputed_claim_ids, scope, allowed_tools, dependencies, attempts/deadline`，只重新计算相关证据节点和下游决定。预算在发请求前原子预留；排队、工具、重试与补查受共享期限和额度约束。未决反例、缺证、超时或未知尝试进入明确的补证或人工状态。

验收用常规高金额案检验复杂度与审批分离，复杂案验证两角色并行且首轮相互隔离、反例命中、仅相关角色补查、无关证据复用。保留可核对的任务时间、调用标识、依赖差异和未执行状态。

## P5 三臂对照、消融与统计

比较三臂为强单 Agent 自主调查、单 Agent 调查/政策/核验三阶段、独立事实和政策并行加反例与局部补查的多 Agent。程序路径作为单独确定性参照和路由覆盖统计。配对单位为冻结 `case_id + repetition`。三臂固定相同模型标识和视觉能力、原始输入和图片字节、业务/政策快照、工具权限并集、时限、尝试及费用上限。记录实际请求、并发与各角色分配。先固定架构对照再测模型路由。消融逐次移除独立首轮取证、专门反例核验、局部补查机制；保留同一程序安全门，预先定义替代行为及配额。结果分常规、复杂冲突及视觉有效/不确定场景，披露分层样本量、失败、超时和未执行。历史 v0.2 报告保留原归属。

| 指标 | 分子 / 分母 |
|---|---|
| 客服一致 | 动作、金额、补证逐项一致 / 同一原输入且双方该项可比的案例。客服获得新增信息的单列 |
| 独立正确或可接受 | 命中预先盲审允许方案集 / 有独立有效标签的可判案例。另报所有计划案例的独立标签覆盖 |
| 错误候选放行 / 正确候选误拦 | 被程序或核验放行的独立判错候选 / 独立判错候选；被程序或核验拦截的独立判对候选 / 独立判对候选。候选版本与核验节点固定，人工改价不计为模型纠错 |
| 关键事实遗漏、政策适用与引用 | 漏项 / 独立标注必要事实；适用判对 / 独立可判的条款适用项；引用支持 / 独立核对的具体引用。无法判断单列 |
| 补查纠错及引入错误 | 同一主张补查前错后对 / 补查前独立判错且两侧可判主张；前对后错 / 补查前独立判对且两侧可判主张。另报补查覆盖 |
| 接管、耗时、成本 | 接管 / 全部已启动案例，另列计划分母及未启动。耗时分别报提交至可见结果与活动执行，公布可用计时分母和删失。调用次数含所有尝试；成本列已知金额、未知尝试及保留预算，分开报告 |

独立复核先冻结输入和判断，再显示 Agent 候选并记录曝光；可接受方案包含多个动作/金额区间/必要补证组合。客服事后操作与新增证据单独记录。无独立标签时相应指标显示不可计算，并列分母、未知、排除理由。用配对样本和按案例聚合的不确定性区间，重复运行不当成独立案例。报告真实浏览器、HTTP、队列、数据库、对象存储和视觉链路各自证据，包含一条常规路径及一条显示反例和补查的复杂路径。
