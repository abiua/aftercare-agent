# P5 聊天调查评测差距与实施计划

2026-11-11。以 [聊天重构计划](CHAT_REDESIGN_PLAN.md#p5-三基线消融与真实端到端)和 [证据决策契约](CHAT_EVIDENCE_DECISION_CONTRACT.md#p5-三臂对照消融与统计)为验收范围。现有 v0.2 数据、已冻结的正式实验和 P4 兼容报告保留原版本、原状态与原解释。

## 当前能力与缺口

| 能力 | 可复用实现 | P5 需要补齐 |
|---|---|---|
| 三种调查架构 | `investigation/graph.py` 内部可选 `strong_single`、`single_staged`、`multi`，硬门禁优先。现有 `AgentService` 已绑定 P4 图版本和会话快照。 | `evaluation/runner.py` 的旧回放以直接业务建案、按类型上传、旧 `start/resume` 为主。需要创建真实隔离会话并回放原消息、无类型原图及确认事项，再从同一版本的冻结调查输入启动三臂。正式结果须验证实际运行配置和实际选中的路径。 |
| 冻结、配对和恢复 | `evaluation/formal` 有私有目录、来源登记、真实尝试账本、稳定 ID、未知后停止以及 V3 按案交错的执行机制。 | `FormalFreezeDraftV3` 继承四条件 `single/multi × strategy` 验证，包事件只含旧业务操作。需要聊天协议版本和独立三臂配置，不能拿旧四条件验证或旧公开 holdout 证明新架构。 |
| 原图、观察、政策 | P2 保留原始和送模图片摘要、转换版本和观察来源。P3 `DecisionScope` 保存文字、原图引用、观察、政策全文和业务状态。P4 记录实际所读工具和来源。 | 评测包缺少聊天事件和冻结原图的资产清单、政策适用快照、视觉输入与尝试绑定。区分同一预观察架构对照和各臂完整端到端，否则共享预观察会被误报成三次真实视觉。 |
| 人工复核 | `eval_reviews` 版本化保存终态 PASS/FAIL/UNKNOWN 与逐项标注；正式包可以携带人审声明，P3 留存原始建议和客服修改版本。 | 现有 `EvaluationService.review` 要求结果先结束，结果页已有候选，无法证明评审先独立判断。正式包的人审来源声明也不证明评审未曝光。缺独立任务、首次判断封存、曝光记录和同输入/新增证据分层。 |
| 运行与评分 | 已有 attempts、使用量、耗时、未知、取消、场景聚合和贡献下钻。旧评测已有政策检索与生产传输取证。 | 新候选、关键事实、引用条件、核验前后同主张和 P3 客服意见无法由旧指标自动推出。P4 已有一次真实文本兼容探测，但其输出是 `INVESTIGATION_PROMPT_LIMIT` 后转人工。不能以 HTTP 200 或程序规则通过代替新质量标签。 |
| 消融 | P4 已具备角色隔离、反例核验和受限补查的节点。 | 当前 ARMS 未登记消融开关。需冻结替代流程，并证明每项只移除预定机制、共用安全门和预算。真实复杂案仍须显示反例及定向补查。 |

## 第一条可验收切片

用明确标记为开发合成的最小聊天包运行程序门禁案、普通案和复杂冲突案。至少一案两次重复。每个 `case_id + repetition` 在隔离数据库及对象范围内按冻结顺序交错三臂，所有计划行保留状态。首轮采用可控模型返回验证程序、权限、统计和恢复。可控返回的输入、输出与费用均明确标注，不能加入正式或真实模型样本。该切片还需通过一个完整盲审界面或私有命令行读取/提交/揭示链路。没有独立人员实际提交时，真实盲审状态保持待完成。

1. 新增 `evaluation/chat` 包。冻结 `chat-eval-v1` 数据：逐条客户原话与附件顺序，受限附件资产原始 SHA、字节数、许可及合成来源，事项绑定、业务事实、政策全文及版本与适用摘要，明确的视觉模式和脚本预期。用有独立实验标识的开发目录，禁止写回 v0.2。包登记要有逐案内容摘要；同源变体及附件复用家族不可跨验证和正式留出。正式包由保管人另行提供，继续执行既有暴露登记。
2. 新适配器从现有隔离 schema/对象存储、`ConversationService`、P2 观察与 P3 授权冻结入口构造输入。复用 P4 内部 `AgentService.start`、现有 `RunAudit`、P3 projector 与业务 `validate_draft`。不从测试或模型输出直接写可执行决定。每臂确认原始输入、政策和视觉承诺一致，允许实际读取、请求顺序和模型生成自然不同。记录真实模型别名/供应方标识、注册表摘要、工具权限并集与实际读取、尝试预算和截止时间。用同样的尝试和费用上限，记录每臂实际配额与核验保留；禁止挪用失败或未知行的额度。
3. 第一切片可选择共享的冻结 P2 观察来固定架构比较输入。每次真实视觉端到端验收另建正常图片通路，核对原图与实际发送图，记录视觉费用及角色模型费用。前者单列共享视觉成本，不按每臂三次付费；后者逐臂自然重跑、实际计费，不能继续称观察内容固定。冻结包不能自行生成真实视觉响应或把观察提升为人工材料审核。
4. 沿用按案交错、稳定执行 ID、结果持久化和失败保留机制。以新 schema/profile 登记三个同模型架构条件，按 `repetition → case → 固定或预登记轮换的 arm` 排序。旧 V2/V3 解释和已冻结配置保持。程序优先门禁三臂均不发请求，记为 PROGRAM 和 0 尝试，单列覆盖；架构模型质量分母不能把三份门禁复制计成模型成功。重启只继续未开始的行；已有尝试或 UNKNOWN 用原账本对账。导出必须带版本和来源，原始照片、收件人标识和私有提示回执留私有权限内。

## 独立复核与新增信息

复用 tester 鉴权和普通事后复核，增加私有 P5 复核阶段记录。最小实现可独立建立评审任务、封存初判和追加曝光/逐项标签三类记录，并以数据库事务、复核者/任务唯一键和版本校验保证先后。独立评审任务展示同一冻结 `input_sha256` 的客户消息、原图、可核实业务证据和政策正文。隐藏模型名称、实验臂、所有候选、程序结果、客服意见及后续新增证据。初判允许多个可接受方案，支持动作、订单行、金额范围或数量、必要补证组合、必查事实和条款适用项；每项可选择不可判。提交后不可改原初判。同一授权评审者才能进入曝光阶段，第一次读候选时在事务内写对应版本/时间记录。其他评审者继续盲态。正式数据的实际独立身份和外部先前曝光仍需人确认；本地记录只证明这个产品入口上的权限和顺序。

客服一致比较使用 P3 原候选版本、客服动作/改价/补证及各自决策输入的有效证据摘要。逐项只比较同输入可判的动作、金额或补证。新增可影响决策的照片、事实、政策或业务状态逐条列出新增证据 ID/版本和冻结前后摘要，单列客服有新信息的案例。仅致谢、回执、纯生命周期变动不制造新证据层；无法取得客服决策输入时标未知。独立正确或可接受率以封存允许集合为准；客服修改只算客服行为，程序/核验是否拦截和模型是否纠错按原候选及实际节点分别计算。

## 后续完整范围

- **消融协议。** 在 `investigation/graph.py` 加内部仅测试可登记的版本化配置。去独立取证使用单次联合初稿，保留相同来源可访问性及后续核验/补查。去专门反例核验用程序检查与常规归并，程序仍对行动安全作最终校验。去局部补查保留反例但将未决项提交人工，不用整图重跑作为替代。每个变体记录实际执行节点及共同预算；模块测试断言只改变被移除机制。先固定模型比较架构，模型路由另建配对实验。
- **新指标与报表。** 给新 scorer/metrics 明确版本，保存源候选、程序/反例核验输出、同一主张的补查前后版本和判定理由。按证据决策契约实现客服一致、独立可接受、错放/误拦、事实遗漏、政策适用/引用、补查纠错/引错、接管、调用/耗时/费用。每项给分子、分母、未知、不可判及排除理由。费用区分已知、未知与预留；耗时区分提交至可见和活动时长，列出删失。按普通、复杂、有效视觉、不确定视觉分层并汇报样本量，按案例而非重复行估计不确定性；小样本只提供描述与逐案配对。
- **真实验收。** 隔离 HTTP/PG/S3/Redis/Celery 验证普通案和复杂案，实际浏览器核对同一会话的原图、候选、人工确认与最终状态。真实视觉需要 wire 和原/送模摘要；复杂案需要看到独立首轮、结构化反例、只补查有关角色、正确节点结果复用，失败和超限仍转人工。受控并发只能证明执行结构，真实模型与人审分别留证。正式新留出要在配置、数据、预算与判定方式冻结后才能解锁；开发样例和历史报告不能升级为正式盲测。
- **实施顺序。** 先批准并落新协议/盲态权限及隔离执行，复用已有评测进度和审计。再补真实模型、消融、三臂统计、用户浏览器和独立复核，最后按验证选择冻结新正式留出。智能模块只需要开放内部版本化实验配置和证据投影。当前 `compact-v2` 由 P4 保存提示版本、摘要和完整私有回执，P5 读取既有证据，不为评测改生产提示或公开原文。
