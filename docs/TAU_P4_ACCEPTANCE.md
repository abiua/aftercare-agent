## 实现与证据边界

P3 的检索能力接入 `conversations/tau_policy.py`、分析队列及调查工具。聊天店铺订单采用原系统的已授权政策目录，独立生成绑定语料哈希的索引；τ-bench 公开政策保留为单独引用来源，不能变成旧店铺订单的授权依据。最终调查工具返回具体原政策引用和检索过程，程序另外检查政策是否适用。独立政策咨询直接整理检索原条款，不调用生成模型。

记忆是从持久会话记录派生的、可追溯的当前事项状态：订单/商品、主诉、最新补充、请求动作、待确认更正、附件及来源。主诉不会被“谢谢”或上传动作替换；更正后不直接沿用旧方案、旧图片观察和不再适用的已审材料。客服在新更正卡中明确选择旧图并说明理由。客户声明仍是客户声明，没有升级为业务已核实事实。

正常案例的 Agent 原始状态为 NEEDS_REVIEW：退款候选通过程序检查，但模型把尚未发生的审批、图片真实性与运输责任列为未决。客服按现有损坏政策采纳原退款选项，没有改写金额、商品或引用；仍保留未决项原始快照，并说明图片真实性/运输责任不作为已证实事实。其后客户确认与财务批准分别记账。这里证明业务流程可用，不把客服意见当独立正确率金标。

两轮实际调用共8次，估算费用 **$0.1150418**，未核对供应商账单。先前权限配置不兼容、预算预留阻断、调查投影版本不一致的失败均保留，见[坏例与修复](TAU_P4_BAD_CASES.md)。本次原图使用合成夹具，材料由测试客服审核；没有在本轮重新测量视觉模型准确率，也没有证明照片真实性。

## 主代理审查与验证

- 更正确认前已暂存、确认后才发布的请求会被标记过期；交错回归验证首次请求及重试均不能混入新证据，已发布原图不受影响。
- “我不想退款了，只想了解退款政策”、撤销/取消退款申请优先按撤回处理，不能恢复旧REFUND；动作不明确继续等待澄清。
- 保留部分原图后仍可发一次补充提示，不因为保留一张图停止补证，也不无限追问。
- 检索在数据库事务外执行，发布时检查租约、会话版本与当前任务；新消息或转人工后旧结果不能覆盖新状态。
- 根代理运行相关后端回归 **96通过、1跳过**。跳过项要求专用迁移PostgreSQL集群，未强行改写其保护条件；本阶段独立真实PostgreSQL业务链和重启另有上述证据。
- 前端49项回归、类型检查、lint与正式构建通过。构建仍提示单个JS包较大；未做前端性能优化或并发容量结论。
- 浏览器用独立Chrome上下文，真实登录客户与客服。政策展示、更正发送、选择原图、客服确认、刷新后状态与权限分别验证；早期选择器歧义及请求提交前读取导致的脚本失败保留在同目录attempt报告，最终不靠重复发送消息掩盖失败。新政策问题在正文直接答复，退款49元回执及刷新通过[最终浏览器验证](../reports/tau-p4-browser-20261112/final-ui.json)，主代理已查看页面截图。

## 当前限制及下一阶段边界

这不是完整τ-bench官方任务成绩。本轮正常售后来自项目已批准的合成店铺案例，τ政策/隐藏任务与店铺业务政策继续隔离。批量质量、多Agent提升、并发和成本路由尚未在P4验收，依原计划后续阶段进行。

当前记忆限于同一会话当前事项；不是跨会话长期用户画像或向量记忆。摘要读取最近250条客户消息，客服原图选择面板显示最近20张；更早照片可读原历史，但本面板尚不支持分页选择。自然语言规则覆盖本轮明确更正/撤回说法，并非任意表达均能可靠识别。

政策咨询采用检索开始时的目录快照，显示版本与生效时间；发布前会检查会话状态，但尚未检查检索期间政策目录是否更新。因此不能宣称发布时必然为最新政策。调查/财务流程仍有独立的适用版本与审批校验。

当前可从 [5224](http://127.0.0.1:5224/) 查看独立演示；常驻服务不启用付费模型，新调查不自动产生真实模型结果。需手动按运行说明开启受控模型验证。原业务数据及历史失败均保留，未进入P5。见[启动、重启与关闭](../infra/TAU_P4_RUNTIME.md)。
