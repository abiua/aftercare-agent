# 调用来源记录的有界验收

本轮验证新增的调用路径和响应观察记录，不评价售后处理质量，也不作为正式验证集选型。沿用项目已配置的 Sol/Terra 模型及用户对必要 API 验证的授权。

- 两个模型各验证默认同步、默认流式路径一次，总计最多 4 次实际 POST；SDK 不重试，程序不补发未知请求。
- 每次最多 900 输出 token。使用当前价格及缓存费用上界、实际序列化输入估算保守预留，四次合计必须不超过 0.05 美元，否则预检拒绝。
- 使用独立持久审计目录和真实 `ModelRunner`、`RunAudit`。每次先保存唯一运行标识和准入记录，再调用默认适配器；不注入假模型响应。合成提示只请求小型 JSON，不涉及客户资料或业务执行。
- 默认仅预检。实际执行必须明确选择执行参数；已有执行报告或状态不得自动开启另一批调用。中断、未知费用和失败原样保留，不为了凑齐成功而换运行编号重试。
- 密钥只在实际执行阶段从已有私有配置读取，不写日志、报告或请求证据。网络观察只保存请求次数、模型、输出上限、响应状态和费用等必要字段。
- 回读持久账本，核对实际路径、响应观察、尝试状态、用量和估算费用。同步/流式标记仅说明本进程默认适配器的观察，不能证明外部身份、实际账单或业务质量。
