# P4 独立政策核验的冻结输入

新 P4 决策范围同时保存两份有区别的政策数据。现行程序选择及其摘要继续支持原业务规则。私有的原始政策目录保留同一次数据库读取的全部版本，包括历史、未来生效、未入选和商品范围不同的条款。目录在写入前受 64 个版本和 96,000 字节限制，超限明确停止。目录版本、原始内容、摘要、决策时点及所选订单行的产品和类别都纳入冻结输入。目录内容变化会使旧调查无法继续提交。单纯时钟流逝不会改变内容依赖摘要。

政策角色看到用户原始陈述、条款版本目录、独立的订单和工单时点及所选产品范围。角色不接收程序选中的版本、退款资格结论或事实角色的结论。顺序基线在政策阶段接收同一个事实阶段输出。它与并行多 Agent 的区别仍是阶段之间的信息顺序，三臂使用同一份原始目录。

搜索在整份冻结目录上返回排序候选，并明确尚未判定适用性。精确读取只允许验证当前范围中的产品，但可以读取当前不适用于该产品的条款，以检查前提。没有覆盖冻结目录的向量检索会保留可见的词法回退。核验角色可以对被质疑的同一政策定向读取另一个冻结版本。

候选提交仍由业务校验决定。最终依据必须是对目标订单行实际适用的准确版本。仅使用相同的政策编号无法让历史版、未来版或错商品版本通过。结构有效但版本不适用的候选保留原动作和金额，程序校验记录拒绝原因。旧范围和已完成历史仍可读取。缺少原始目录绑定的未完成 P4 运行停止继续使用模型。

目前证据来自真实业务规则的受控回归。未调用提供方。P5 盲评应使用原始目录、时点和产品数据，避免把程序结论混入人工判断材料。
