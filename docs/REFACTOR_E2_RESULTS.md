# E2 五组正式对比结果

2026-11-13。200次主运行及9次预先允许的补跑均已结束，最终200个任务均有官方评分。费用仍有6笔未结算，不将它们按0处理。

**结论：没有证明多 Agent 整体优于简单方案。** M1比强单多成功1题，少放弃3题，但比自检少成功2题；低成本单 Agent 与强单自检并列32/40。优先保留简单路径，把独立审查作为待针对性改进的可选能力。此报告不自动改变产品默认配置。

## 执行依据

- 用户授权执行第3步，按 v2.1 + v2.2 冻结方案运行。代码提交 `bc42c3b`，冻结提交 `fc4e39c`，38个冻结文件全程未改变。

- 每题五组使用同一官方任务和种子；强模型 `gpt-6.1-sol`，低成本执行者 `deepseek-flash`，模拟客户 `gpt-6.1-terra`，官方裁判 `gpt-5.4-mini-2026-03-17`。
- Agent最多48次调用、模拟客户24次、裁判1次，输出1500 token，100步/900秒，请求120秒；主批次并发6，补跑并发1。

## 协作实际发生了什么

- S2自检62次，要求修改8次；M1独立审查64次、修改7次、专家8次；M2独立审查73次、修改6次、专家18次。M2有1次审查回退，专家无不可用记录。这些数字是调用/事件次数，不是独立纠错成功数。
- 第111题：M1审查发现执行者过早转人工，要求解释哪些修改可做、回答已查到的地址问题，并保留客户要求暂停的修改；M1最终官方成功，S1失败。这是可检查的正例，单次对比不能证明因果。
- 第27题：M1两次反对转人工并要求继续核对换货，但最终仍被官方判失败。要求继续处理不等于处理正确。
- 第74、111题M1成功而S1失败；第56题相反。完整逐题结果及角色费用见 JSON，避免只展示成功例子。

## 审计与限制

- 检查了200条主排程、9条补跑的身份/种子/原记录哈希、200个最终评分与官方轨迹一致、所有调用角色和模型、每题上限、唯一计费回执、冻结源码哈希及合计额度。
- 分析文件 `complete=false` 是费用未完整结算导致，包含历史S0也有1笔未结算；本轮200项评分已齐全。不能把评分齐全写成费用核对完成。
- S0只引用历史29/40，既非同次运行，也不计入本轮费用。
- 设计参考了这些40题的首轮失败，属于已见题目的结果；每题一次，不能推出未见任务的泛化能力或稳定胜率。
- 本轮验证评测内核，不等于产品浏览器、并发能力、完整复杂纠错或真实支付验收。产品此前基本验收的范围保持不变。
- 本轮没有预先冻结普通/复杂分层及新的消融排程，因此不事后挑选子集声称多Agent更好；也没有新增付费实验。
