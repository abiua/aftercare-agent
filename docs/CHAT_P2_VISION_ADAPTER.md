# P2 视觉适配接线

状态为适配器和受控验证。P2 会话调度、权限联调及真实提供方图像理解另行验收。

- 领取当前会话事项的分析任务后，从同一冻结输入读取附件标识、所属消息、登记 SHA-256、类型和字节数。以该用户及该会话的授权读取函数调用 `prepare_photos(sources, read_authorized)`。最多 6 张，总原图 8 MiB。适配器核对原始字节、类型和尺寸，转换为最大边 768 像素的 JPEG。记录实际发送字节的摘要、尺寸及 Pillow 转换版本。原图地址、对象密钥和图像内容不写入审计事件。
- 用 `observe(model, audit, photos, preferred=alias, input_binding=turn_digest, data_scope=scope)`。合成验收用 `simulated_case`，客户原图用 `customer_attachment` 并要求提供方明确允许此数据范围。输出的结构化观察均为 `MODEL_OBSERVATION/UNVERIFIED`。适配器按图编号匹配授权来源，禁止自动写材料类型、审核结论、归责或处置动作。由会话任务对当前代次、范围和租约校验后，持久化观察并生成公开投影。
- `audit` 沿用 ModelRunner 协议，提供费用检查与原子预留、提供方槽位、持久尝试回读、结果结算和当前任务准入。视觉固定别名、同步、无工具、一次尝试。未知状态保留预留，不重放为新请求。照片数量、低细节输入和已核验的每图 token 上界参与上下文判断与费用预留；文本保守按 UTF-8 字节估计。兼容证据必须覆盖当前提供方、模型、协议与 768 像素低细节发送配置。不得用一次样本实测用量代替可解释的配置上界。
- 激活模型需独立登记 `vision=true`、核验日期、兼容报告版本和 `vision_input_tokens_per_image`。现有文本配置摘要保持兼容，缺少视觉实证的候选不得启用。受控模型探针复用相同 JPEG 和 LangChain 请求构造，先用只含合成图的明晰区分、标签、模糊、矛盾与图片内指令条件。最多四次外部请求，固定每次 900 输出 token 上限及预先核准的总费用帽，无重试。报告应区分实际图像传输和响应、用量与费用来源、独立观察判定，以及仍待验收的完整会话链路。

## 已取得的真实传输证据

首轮 Terra 经实际 Responses HTTP 发送两批 96×64 合成标记卡，发送 JPEG 摘要与适配器记录一致，两次响应均可解析。清晰卡片只返回内容不确定，未抽取印刷字样。模糊卡片返回模糊与内容不确定。登记价格和返回用量估算为 0.002815 美元。验收范围为真实图像传输，观察实用性仍待验证，生产视觉能力未启用。[原始探针](../reports/chat-vision-compatibility-live-20261111.json) · [独立复核](../reports/chat-vision-compatibility-review-20261111.json)

后续两次请求使用本地 640×480 合成图卡和相同内容的模糊变体。无请求预检冻结原图和发送图摘要，并将前两次已知估算与剩余预算合并。图卡只提供印刷标记和模糊条件，商品损坏、标签歧义及图片内指令仍需专门验证。费用额度为登记上下文和价格下的估算，实际供应商账单另行核对。

分析任务每次准入和发布都核对当前账号启用状态、客户角色与会话归属。费用未知保留预留并阻止视觉观察发布。晚到结算以独立字段追加至原尝试，保留原 `UNKNOWN` 和中断时间。
