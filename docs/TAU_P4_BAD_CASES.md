# τ P4 接线失败与恢复

## 模型注册缺少聊天权限

O9902 首次调查选中标准单 Agent 路径，但历史共享注册表的模型只允许旧工单上下文，输出上限为 900。应用返回 `NO_COMPATIBLE_MODEL`。账本显示供应方尝试 0 次，估算费用为 0。随后为同一个隔离工单启用已有验证记录的分析模型，配置合成客户对话权限和 4096 输出上限。历史共享注册表保留原样。[首次尝试](../reports/tau-p4-live-business-20261112.json)

## 最坏用量预留阻断后续调查

第二次调查的三次 Responses 请求均返回 HTTP 200，估算费用合计 $0.0419855。调查确实调用了 `search_applicable_policy`，从冻结业务政策目录检索到具体版本，包括 `POL14:1.0`。第四轮的最坏用量预留超过当次 $0.12 上限，在发出供应方请求前返回 `MODEL_COST_BUDGET_EXHAUSTED`。该运行保留为 `NEEDS_REVIEW`，没有完成退款候选。[预算阻断](../reports/tau-p4-live-business-scoped-20261112.json)

## 调查与投影配置不一致

前两次调查运行使用 V7，恢复投影的 worker 关闭了调查开关，读取冻结数据时落到 V6。投影以 `INVESTIGATION_PROMPT_VERSION_CHANGED` 安全停止。后续 API 和 worker 统一使用 V7，常驻 worker 保持无付费模型，beat 只调度分析和恢复任务。前两次阻断行保留。最终运行由同一工单的新输入触发，投影为 `PUBLISHED`。[最终运行](../reports/tau-p4-live-business-final-20261112.json)

## 候选和审批边界

最终运行五次真实 Responses 请求返回 HTTP 200，估算费用 $0.0730563。模型提出 O9902/L01 的 49 元退款候选，程序检查通过，同时记录审批缺失、图片真实性和运输责任未核实。客服采用原模型退款选项，商品行、金额、证据、政策引用及选项正文逐字段一致。客服说明已审材料满足当前损坏处置条件，图片真实性与运输责任仍无结论，财务审核仍需完成。原 Agent 快照及未决项留在历史中。材料审核为合成验收登记，客服和财务请求分别使用不同角色凭据。客户确认后，未审批执行被拒绝，独立审批后只产生一笔模拟回执。相同及不同幂等键重试均返回原回执，订单累计退款仍为 49 元。两次付费阶段共 8 次调用，估算 $0.1150418，供应方账单未核对。[最终闭环](../reports/tau-p4-live-business-final-20261112.json)

## 记忆边界与浏览器审查

主代理交叉审查发现三个问题并在交付前修复：更正确认之前的暂存上传可能在确认后混入新证据；撤回退款和政策咨询写在同句时可能恢复旧退款诉求；保留一张旧图后停止后续补证。修复后有真实暂存/发布交错回归、混合撤回表达及补证次数检查。原始已发布消息和原图继续保留。

浏览器首次定位按钮时未适配 Ant Design 的“登 录”空格，随后“公开回复”与“发送公开回复”匹配歧义、提交确认之前读回旧状态、创建消息预期200而实际201等脚本问题已修正；失败报告保留在 `reports/tau-p4-browser-20261112/attempt*.json` 及 `final-ui-attempt1.json`，不属于业务执行失败。恢复时读取已有提交状态，不盲目重发更正或重复创建工单。截图审查另发现退款成功页仍显示先前自动分析失败的顶栏；现在以当前工单已确认成功回执为准，不再显示该旧顶栏，历史消息仍保留。
