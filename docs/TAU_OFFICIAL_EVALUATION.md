# 官方 Retail 三组评测

## 本轮目标与状态

替换自定义案例，使用官方 τ²-bench Retail 测试集及其原版评分器。全量 120 次已结束。一次 API 异常在独立目录补跑后获得官方分数；多 Agent 的一个任务用尽 48 次调用预算，保持未完成、不补跑。最终 119 个任务/架构组合有官方分数，全部 120 个组合计入各组分母。

固定源码版本：`da0835f6c67baef58bdda18f2a3b037dfb3a1754`。项目此前引入的就是 τ²-bench Retail，本轮沿用相同版本，核对数据 SHA-256。测试集共 40 个官方任务，强单 Agent、单 Agent 三阶段、多 Agent 各运行一次，计划 120 次。该提交实际位于官方 v2.0.0 之后，分数口径与外部可比范围见[版本说明](TAU_OFFICIAL_SETUP.md#版本说明)。

## 如何判断成功

调用官方 `run_simulation` 和 `EvaluationType.ALL`，保留每个任务自己的 `reward_basis`。数据库条件由官方参考操作推导目标状态，再比较实际状态；不要求模型逐字复述标准答案或照搬固定调用路径。需要自然语言断言的任务由官方评分器处理。参考答案和模拟客户的隐藏要求不传入 Agent。

- 官方得分为 1 计成功；总成功数除以该组计划的 40 个任务。
- 未运行、运行异常和未能评分单独列出，不悄悄缩小分母。
- 官方提前终止得分仍保留，区分模型业务失败与工具/网络故障。
- 每任务仅一次，不能当作多次重复稳定性指标，也不能证明生产环境客户满意度。

## 公平对照

三组固定 Agent 模型 `gpt-6.1-sol`，同一官方工具集、原始信息、调用上限和环境步数上限。客户模拟器统一使用 `gpt-6.1-terra`。官方需要的评审模型独立计费。所有角色调用都计入同一个 Agent 预算，多 Agent 不额外领取额度。

强单 Agent 可以自主多步调查；三阶段组依次调查、分析与执行；多 Agent 使用独立上下文的只读取证、政策检查及有界补查。官方 Retail 政策要求一次调用一个工具，三组均遵守；多 Agent 的首轮模型推理并行，实际工具查询串行。只有公开执行器可调用写工具，私有角色的查询保留审计记录。最终实现与预算以正式批次冻结的 manifest 为准。

## 费用与原始记录

官方测试集第一个任务的三组接线检查共花费约 $0.105784。全量批次冻结上限为 $30、8,760 次调用；每任务三组均为 Agent 48 次、客户模拟器 24 次、官方评审 1 次，最多 100 步、900 秒，6 个任务并发运行。模型、客户模拟器和评审的调用、token、估算费用分别记录。未知费用不按零处理；请求不自动重试，已启动批次不自动重放。

原始官方对话、评分、私有角色查询和预算账本放在隔离运行目录，发布到 `evidence/tau_official/latest.json` 的摘要供测试中台读取。页面不向客户暴露隐藏任务或参考答案。

## 旧案例清理

旧自定义评测退出用例库和统计，相关案例文件、评分材料、P8/P9 批次及备份按范围删除；删除路径清单只记录路径，不保留案例内容。已有订单、工单、聊天及审批数据不动。OCR/RAG 的技术测试与官方 Agent 对比用途不同，继续保留。

## 复现

```sh
scripts/aftercare-eval.sh official run --scope full --directory .runtime/tau-official-new --agent-calls 48 --user-calls 24 --max-usd 30 --max-calls 8760 --concurrency 6 --run-timeout 900 --live
scripts/aftercare-eval.sh official summarize .runtime/tau-official-new --publish
```

每次使用新目录，不重放已发出的请求。此次采用针对官方工具的架构适配器，官方环境与评分器不改；它衡量三种架构在官方文本任务上的表现，不等同于整套售后聊天、RAG、图片和审批流程的端到端验收。

## 技术异常补跑规则

主批次中 API 异常且没有官方分数的条目，可以在独立新目录补跑一次，保持原任务、模型、提示词、随机种子与单条预算。已有官方分数（包括 0 分）的条目不补跑，不择优取分。主批次原始记录不改；合并展示明确标注补跑，费用计入首次尝试，未知费用保留待核实。本轮补跑总上限 $3。

## 工程验证范围

官方适配器、预算和评分接线的离线测试通过；真实浏览器可读取官方表格，原会话找回和失败消息仍可见。扩大到整个现有后端后，发现 24 项聊天模块回归失败：其中 19 项已补齐测试替身并通过定向复测；其余 5 项涉及工具输入预算、无模型时的人工接管与投影状态、未确认新事项后的照片分析。没有为通过测试修改这些业务断言，也没有把它们混入官方成功率。详见 [工程验证记录](TAU_OFFICIAL_ENGINEERING_REVIEW.md)。

## 实际结果

三组 Agent 均为 `gpt-6.1-sol`，模拟客户为 `gpt-6.1-terra`，官方自然语言断言评审为 `gpt-5.4-mini-2026-03-17`。下表含唯一一次 API 技术补跑及其首次尝试成本；每题不因分数低而重跑。

| 架构 | 官方成功 / 计划 | 成功率 | Agent 调用 | 耗时中位数 | 已记录费用（Agent+模拟客户+评分） |
| --- | --- | --- | --- | --- | --- |
| 强单 Agent | 29 / 40 | 72.5% | 467 | 39.57 秒 | $5.49213225，另 1 笔请求待核，预留 $0.038076 |
| 单 Agent 三阶段 | 25 / 40 | 62.5% | 805 | 92.35 秒 | $8.262047 |
| 多 Agent | 25 / 40 | 62.5% | 800 | 66.85 秒 | $8.57151225 |

本轮强单 Agent 的成功率高 10 个百分点，耗时和已记录费用也更低。逐任务看：23 题两者都成功、6 题仅强单成功、2 题仅多 Agent 成功、9 题都未成功；“仅强单成功”包含那条多 Agent 预算耗尽的任务。不能据此宣称多 Agent 普遍更好。每题只有一次计划试验，尚未测重复运行稳定性。

多 Agent 实际执行 134 次私有只读查询，有独立角色和核验记录；不是三个角色名称包装同一次回复。这些调用没有带来本轮总体收益，后续优化应先在训练集定位原因，而不是调整测试集答案。

主批次原始结果：强单 28/40（另1条 API 异常无分数）、三阶段 25/40、多 Agent 25/40（另1条预算未完成）。任务79强单在技术补跑中得到1分；任务101多 Agent 因预算耗尽没有官方评分，按失败保留在40题分母里。正式报告保留这两种情况的差别。

比较批次与技术补跑共 2,797 次请求，2,796 笔已记录费用合计 $22.3256915，1 笔保留 $0.038076 待核预留。另有接线检查25次请求/$0.105784；本轮已记录总费用 $22.4314755。费用来自用量与冻结单价，不是供应商账单。
