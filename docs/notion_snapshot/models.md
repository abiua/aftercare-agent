## 路由的三种职责

| 类型 | 负责的问题 | 项目安排 |
| --- | --- | --- |
| 任务路由 | 当前任务适合哪个已验证模型 | Python规则优先，不训练分类器 |
| 故障切换 | 主调用暂时不可用时如何停止／重试／切换 | 兼容备用模型、有界尝试、冷却 |
| 实例负载均衡 | 同一模型多个部署如何分配请求 | 有实际多实例需求再引入LiteLLM |

LangGraph条件边是业务流程路由。ModelRouter不决定退款资格、审批有效性或业务状态，也不能增加角色工具权限。

## 调用链与接口

业务节点 → 构造TaskSpec → 先过滤能力／数据范围／预算 → ModelRouter选别名 → 调用适配层 → 输出验证 → 接受／修复／升级／转人工。

TaskSpec包括任务类型、所需工具／结构化输出能力、估算上下文token、输出预留、允许提供方、总截止时间和剩余预算；由程序构造。分类不明先追问，或在预算内由已验证分类能力辅助，不能凭模型自报置信度授权。

注册表保存别名、提供方、实际模型及版本、endpoint配置引用、工具／结构化／流式能力、上下文与输出限制、费用表日期、可接受数据范围、健康状态、备用候选和兼容测试版本。只保存环境变量名，不写Key。

RouteDecision保存候选排除原因、最终别名、原因码、路由配置版本和预算快照。价格、能力和健康信息必须有来源及更新时间，不能把更贵等同于更可靠。

U2只有一个通过验收的模型时，输出单候选决策用于观测；不把两个别名指向同一模型宣称为多模型路由。U5增加至少两个实际模型并分别验收后启用选择；同提供方两个模型不代表供应商级容灾。

## 初版规则

| 情况 | 动作 |
| --- | --- |
| 格式明确且唯一的订单号 | 可先用程序解析；含歧义时澄清 |
| 意图识别、普通回复整理 | 经本项目评测合格的economy候选 |
| 多证据比较、复杂方案分析 | 经本项目评测合格的analysis候选 |
| 金额、归属、政策效力、审批 | 确定性程序处理，不交给模型裁决 |
| 缺照片、缺订单、缺有效政策 | 追问或补查；换强模型不能补造事实 |
| 输出schema不合法 | 返回错误字段，预算内修复一次；仍不合格且有兼容候选才升级 |
| 证据／权限／金额硬约束失败 | 不以升级覆盖规则；明确纠错或人工接管 |
| 暂时超时、429或服务异常 | 按错误类型和剩余时间，有限重试或切换 |
| 密钥无效、权限拒绝、参数契约错误 | 停止并报告配置问题，不循环换模型掩盖 |
| 政策冲突无法消除、预算不足、无兼容候选 | 输出明确结束原因或转人工 |

上下文长度只用于可容纳性过滤，不是能力评分。缺上下文空间时走受控裁剪／摘要或停止；不能静默截掉规则、必要证据和工具结果。

## 重试与切换约束

初始设计预算：每次逻辑模型请求最多3次实际尝试（首次＋至多2次额外尝试），其中同模型技术重试最多1次、语义修复最多1次、模型切换最多1次；这些机会共享总上限，不能相加后超额。每个案件版本主动处理周期初始设12次模型尝试／120秒，均是待验证配置，人工等待单独计时。冷却、退避和已失败调用都计入相应记录。

唯一重试责任在模型调用层；SDK、图和网关不得再各自叠加模型重试。LangChain middleware可作为该层的实现机制，接入后用实际调用数测试确认顺序；若以后改由LiteLLM负责，同步关掉外层重复机制。无重试配额不能调用备用模型。

切换前验证工具参数schema、调用编号与结果配对、结构化输出、上下文、流式消息和提供方数据范围。重新绑定同一权限范围工具，不能复用不兼容的已绑定模型对象。

只在完整模型调用边界切换。部分流式响应标为未完成，前端丢弃该草稿或显示新尝试；不能把两家模型的半段回答拼成一个。工具调用必须完整解析且通过校验才执行。

模型重试不得重放已执行的业务动作。图恢复先查运行记录和业务账本，沿用原幂等键；连接超时可能仍有费用，未返回usage时记录成本未知，不填零。

## 技术落点

| 模块 | 实现选择 |
| --- | --- |
| 路由业务函数 | Python 纯函数，由 GPT 完整实现并验收；程序校验配置与输入输出 |
| 注册表与契约 | Pydantic＋版本化配置 |
| 集成 | 统一模型适配接口；采用create\_agent时再用兼容middleware挂接 |
| 重试与fallback | 可用LangChain ModelRetryMiddleware／ModelFallbackMiddleware；不是装包就自动接入当前自写循环 |
| 多部署治理 | LiteLLM按需求引入，应用任务规则仍独立 |
| 审计 | PostgreSQL保存run／逻辑调用／attempt、原因、模型、耗时、usage、估算费用和失败 |

[LangChain官方中间件](https://docs.langchain.com/oss/python/langchain/middleware/built-in)确实提供模型重试和fallback；具体参数及顺序在锁定版本后测试。错误耗尽时返回明确失败，不能把技术失败伪装成正常助手答复。

[LiteLLM Router](https://docs.litellm.ai/docs/routing)提供多部署调度、冷却与回退能力；这不是按业务质量自动挑选模型的证据。

[RouteLLM](https://github.com/lm-sys/RouteLLM)支持学习型路由，但预训练模型与数据不同于本项目，阈值仍需售后验证集校准，部分路由还有额外嵌入调用依赖。首版不安装、不训练，不直接引用其收益作为本项目结果。
